# a-stock-tracker

收盘后的 **A 股个股研究助手**：先研究一家公司，核查财报、反证与资料缺口；需要时再单独确认价格纪律参考。初筛是寻找公司的可选入口，不是必经流程。

## 产品目标与规格归属

帮助用户回答：为什么值得继续研究？最强反证和资料缺口是什么？依据截至何时？价格到哪里说明判断失效？证据不足时明确说明，不凑结论。不承诺收益，不提供仓位管理或自动交易，不要求维护笔记、关注列表或已阅状态。

本 README 维护产品目标、网页主流程与验收。模块、数据和安全合同见 [架构](docs/architecture.md)；管理员配置、部署和高级 CLI 见 [运维](docs/operations.md)；历史验证结论见 [离线验证](docs/offline-validation.md)。[peer-screen-v1](docs/specs/2026-09-22-peer-screen-spec.md) 只维护财报研究规则。UI 场景和表达分别见 [PRODUCT](PRODUCT.md)、[DESIGN](DESIGN.md)。

网页是 FastAPI + Jinja2 服务端 HTML（原生表单、链接与可展开依据，一个同源脚本）；本机 AI Agent 与 Skill 通过 MCP 服务（`python -m a_stock_tracker.mcp_server`）复用同一接口。MCP 注册为本机客户端按需配置；历史上线记录见 [CHANGELOG](CHANGELOG.md)，实际运行状态须按[运维](docs/operations.md#服务状态探针与排障)核验。

## 本地演示与验证

需要 Python ≥3.13、uv。demo 仅 loopback 与明确标记的合成数据，不需要真实凭据、不产生行情或模型费用。

```bash
make setup
make demo                    # 只启动 Web（http://127.0.0.1:8551，合成数据）
make check                   # 离线测试、lint、格式、类型与 diff 检查
.venv/bin/python -m playwright install chromium
make test-mobile             # 真实浏览器点击，含 360/390/430px
```

测试仅使用临时目录、合成数据与模拟接口。`make test-mobile` 同时打印 10 Mbps / 80 ms 下的合成冷启动耗时与传输字节；手机尺寸浏览器回归不等于生产、本人 OAuth 或真机验收。

## 网页主流程

1. 首页选择 **研究一家公司**，输入代码。`/analysis` 默认进入单家公司财报研究；已有初筛候选也可预填代码进入。
2. 核对公司、范围、预算和固定的 provider/model，显式确认后开始。单家公司最多 100 次数据请求、30 分钟、一份报告。模型最多调用 10 次，每次本地等待 240 秒；输出 token 与费用无硬上限，本地超时不保证提供方停止计费，失败也可能收费。必须接受页面列出的费用边界，预算或模型变化须重新确认。
3. 网页查看进度与结果。报告先展示状态、资料日期、最强反证全文和前三条缺口，再读业务、财务、估值方法、改变判断的条件及引用。未通过原文/证据复核不展示草稿；来源 URL 仅作纯文本，不渲染模型 Markdown、图片或可点击外链。
4. 读完报告后，按需进入 **独立价格参考（不调用模型）** 并再次确认该请求。程序只计算显式 1–5 家沪深主板公司的参考，网页预算最多 20 次数据请求、15 分钟；不自动运行、不发现全市场机会，不因旧趋势或 8% 距离门槛排除资料完整的公司。后续五个交易日是参考有效期，不是持有建议；到期隐藏观察线、失效线和距离。
5. 首页重开进行中或最近十条研究链；进行中的页面自动刷新进度。受理未知时核对原编号，不另起一轮请求；同编号核对不会重复执行已受理请求，但不是对提供方实际费用的保证。退出或会话到期后不再显示私有结果，也不自动取消已确认的有界研究。报价被明确拒绝时保留输入、更新报价并清除确认。

### 可选：从初筛找公司

首页次要入口 **从初筛找公司** 不要求先填代码或选行业，不调用模型。默认先筛选 0＜PB≤3、总市值≥50亿元的股票，再采集财报；这是控制采集量的工程门槛，未经收益验证、可能漏选，不限制指定股票研究。首次最多 1500 次数据请求、3600 秒，不保证覆盖全市场或产生候选。

结果先展示每组前三名候选与研究动作，完整排名可按行业或代码、名称分页查看，采集依据随后展开。排名仅代表资料完整的筛后行业池，不是全行业前三或跨行业投资总榜。展示本轮用量、停止原因、累计覆盖、未覆盖及缺口；无候选也保留原因。进入候选研究仍须单独确认。

有未覆盖股票时可明确确认新增预算继续初筛；只处理原冻结范围中尚未覆盖的股票，不自动重试缺口、不改写原批次。同日同预算可复用已校验结果；续跑和复用在首页合并为同一研究链。冻结超过七天或规则变化须开始新批次。详细报价、资格与恢复合同见 [架构](docs/architecture.md#网页研究请求合同)。

### 边界

研究结果保存在各请求自己的私有批次；原 `/published` 与 `/opportunity/代码` 发布入口生产从未配置，已随 Flet 退役（返回 404）。生产未配置研究接收器时给出管理员连接说明，不显示虚假完成结果，不要求日常用户改跑终端。

- Web 只转发本人已确认的请求，不持行情/模型凭据、不打开私人数据库。独立接收器使用已授权的 Hermes 或 pi 运行时，固定 provider/model；没有自动排队、恢复、收费重试或定时研究。
- `market-research-v1` 财报资格、排名及复核通过都不等于投资建议或效果证明。
- 价格参考仅由程序离线计算，量价只作风险纪律参考；历史 `swing-observation-v1` 仅有离线重放结论（未证明稳定超额），前瞻验证未积累样本即放弃，相关代码不再维护。
- 不做多用户、个人笔记、自选关注或自动交易系统。

## 验收与运行授权

- 手机无需终端即可完成输入公司 → 成本确认 → 研究 → 摘要/反证 → 引用 → 可选价格确认 → 返回/退出。
- 初筛候选优先、完整排名可核查；财报保留反证、日期与缺口，复核失败不展示草稿。
- 价格计算不调用模型；新旧规则分别识别，到期自动隐藏行动价位，不改写历史产物。
- 认证、预算、同编号幂等、原子发布、完整性校验与迟到结果隔离不退化；失败与未知用量不冒充成功或零费用。

### 回归与发布门槛

以下是后续变更的回归与发布门槛，合成验收由 `make check` 与 `make test-mobile` 覆盖；任一项失败即阻断切换，不以平均表现抵消。

- 用户流程：上述手机主流程在 360/390/430px 真实点击完成，含报价变化、重复提交（同编号只执行一次）、受理未知后同编号核对、退出与价格到期隐藏；长中文报告可读，状态不只靠颜色区分。
- 冷启动：10 Mbps / 80 ms、新浏览器上下文下，已认证首页可操作 ≤2 秒（单项冒烟，不做 P95 统计）。
- 报告状态：网页、Markdown 与 MCP 对同一报告给出一致状态，复核通过的报告不再出现“未完成”；覆盖页数、修复与剔除条目、失败阶段分别可见。
- 安全：认证、在途撤权、CSRF/来源、Host、转义、CSP、`no-store`、编号幂等与凭据隔离均有用例逐条覆盖。
- MCP：在合成接收器下，Agent 不经浏览器完成查询、报价与提交；暂存报价过期或超出渠道每日限额的提交被拒绝，同编号重复提交返回既有状态且不重复计数。
- 真机：至少一台记录了型号、系统和浏览器的手机完成主流程；未完成标为 pending。生产 OAuth 与切换后观察未执行时标为 NOT_RUN，不与合成验收混同。

源码和离线验收不证明已部署或真实研究可成功。真实行情/财报/模型请求须确认范围、模型与费用边界；通知、部署、重启、定时启停及历史数据操作另须明确授权。旧版本记录见 [CHANGELOG](CHANGELOG.md)，不代表当前生产状态。
