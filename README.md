# a-stock-tracker

面向数周至数月的 **A 股波段机会助手**：**看候选 → 看懂 AI 解释与反证 → 等待价格条件**。帮助减少无效信息，不承诺收益、不提供仓位管理或自动交易。

## 产品目标与规格归属

**目标：让用户在收盘后，为数周至数月的 A 股波段研究找到值得继续核查的候选，理解支持与反对证据，并知道什么价格条件下重新评估、什么情况下放弃。** 输出是有边界的观察与核查条件，不是交易指令；不要求用户维护笔记、关注列表或已阅状态。

用户应能回答四个问题：为什么值得观察？最强反证与未核查风险是什么？依据截至何时、条件何时过期？何时重新评估或放弃？没有合格观察或证据不足时，明确说明，不凑推荐。

- **产品目标、首版范围与验收由本 README 维护**；数据、发布和安全合同由 [架构](docs/architecture.md) 维护。
- **当前首版只是目标的一部分**：`--codes` 显式提供候选池，程序筛出量价观察并解释；尚未解决候选池自动发现、完整风险证据和持续条件跟踪。后续五个交易日是条件有效期，不是数周至数月的持有建议。
- **[peer-screen-v1](docs/specs/2026-09-22-peer-screen-spec.md) 仅是独立财报研究的子规格**，不是项目总 spec，也不是波段候选准入或优先级规则。保留该批处理不意味着把它作为主产品演进方向。

## 核心范围

- **默认首页 `/`**：少量波段观察候选，先解释为什么值得等、什么情况放弃，再展示价格条件；公司详情在 `/opportunity/代码`。没有合格候选就明确不推荐。不包含笔记、主动更新、关注与已阅。
- **swing-observation-v1（首版）**：显式指定 1–5 家沪深主板公司，以完整日线计算趋势、相对强弱和观察条件；AI 解释并经另一次模型调用复核。**不是全市场自动精选，也未覆盖板块资金、公告催化和完整财务风险，不可当作综合荐股。**
- **旧工作台已删除**：`/research`、`/discover`、`/company/*`、`/jobs/*` 返回 404，不保留兼容入口。专用工作区/worker/笔记/已阅链路及 demo 工作区初始化已移除。历史私人文件仍保留，不挂载给 Web。
- **market-research-v1**：独立全市场财报研究批处理，维护共用的财报资格、年度选择与排名公式；不保留个人参照筛选或关注列表排名接口，不自动转成波段候选。

不恢复 QFQ、收益回测、分红物化、交易账户、Framework A 或 Agent 调度平台。价格相对强弱仅作筛选事实，不证明未来收益。

## 本地开发

需要 Python ≥3.13、uv。demo 仅 loopback、合成数据，不需要真实凭据。

```bash
make setup
make demo                    # 仅启动只读 Web；无数据库初始化或 worker
make check                   # 离线测试、lint、格式、类型与 diff 检查
.venv/bin/python -m playwright install chromium
make test-mobile             # 真实浏览器点击，含 360/390/430px
```

验证仅使用临时目录、合成数据与模拟接口，不调用真实行情或模型。中文字体随包提供，见 [字体说明](assets/fonts/README.md)。

## 网页选股与研究（用户主流程）

登录后点击首页 **开始选股与研究**，不需要用户跑终端命令：

1. **财报初筛找候选**：不填代码、不选行业，先用同日批量数据筛出 **0＜PB≤3、总市值≥50亿元（不设上限）** 的股票，再逐股采集财报。门槛是控制采集量的工程默认值，未经收益验证、可能漏选；仅用于初筛，不限制指定股票研究。最多 400 次数据请求 / 30 分钟，不调用模型。显示覆盖、未覆盖和缺口，不保证覆盖全市场或产生候选；仅筛后池资料完整的行业形成候选，展示为“筛后同业排名”，不是完整行业前三或波段推荐。同日同预算的普通请求可直接查看已有结果。若仍有未覆盖股票，入口会明确切换为“确认新增预算并继续初筛”，也可从原结果进入；每次新增最多 400 次请求 / 30 分钟，不调用模型，不自动续费。继续时复制并校验原检查点，只扫描尚未覆盖股票，保留原批次和原冻结日期；不重新请求已采集财报，也不自动重试资料缺口。冻结资料超过七天或筛选规则变化不能继续，应明确开始新批次；旧结果仍可查看，不按新门槛改写或复用旧规则批次。
2. **指定股票量价研究**：输入 1–5 个沪深主板代码（如 `600519`），或从筛选结果点击“核对量价条件”。最多 20 次数据请求 / 15 分钟；由交易日历选择最近一个已收盘日期，逐家公司生成解释与另一次复核。两次调用不表示两个不同模型。
3. **单家公司财报研究**：输入一家代码或从候选点击进入，最多 100 次数据请求 / 30 分钟 / 一份报告。仍须通过现有资格、原文及证据复核，不保证有可用报告。
4. 页面展示范围、模型身份和预算；勾选成本确认才可启动。模型研究明确展示调用次数、本地超时及“输出 token 与费用无硬上限”，须勾选接受该费用边界；本地超时不保证提供方停止生成或计费，失败也可能收费。费用边界随报价提交并留存，未包含新边界的旧确认不能启动新研究。服务端核对同一预算/模型报价，配置变化拒绝启动。受理未确认时核对原编号，不另起一轮收费。
5. 直接查看进度、覆盖、失败和结果；最近十次网页请求提供重开入口。退出或切页隐藏当前内容，但已确认研究继续受预算限制。量价结果及到期隐藏在每次读取时重新校验。

初筛使用2000积分可用的普通 `fina_indicator`，不依赖 VIP 接口；财报批处理每次数据请求前至少间隔0.5秒（单进程至多约120次/分钟），其他程序共用账户仍需另行分配额度。缺失/非正总市值在无法确定排除时记为资料缺口，不以零填充；`total_mv` 原单位万元，50亿元对应500000万元。结果同时展示冻结门槛、采集前排除/缺口/入池数量及当前覆盖。

`make demo` 可完成上述合成闭环，无真实请求或费用。生产研究服务未配置时明确提示管理员连接，不展示虚假的完成结果。原有已发布批次的只读浏览入口仍可用；退役路径不恢复。

网页研究结果从“最近研究”重开，不自动加入首页机会列表；首页仍读取单独配置的 `OPPORTUNITY_ROOT`。因此网页研究已完成而首页无批次，并不表示研究结果丢失。报价变化被拒绝后，当前需返回研究入口重新加载并确认；原页“核对原请求”不会刷新报价。

### 管理员一次配置（不是用户操作）

独立宿主研究进程复用当前已安装的 Python 环境及已授权模型运行时。Web 仅挂载私有 **socket-only** 桥目录，不挂载研究产物或历史数据，也不获得行情/模型凭据。

- 根据 `.research.env.example` 创建 Git 忽略的 `.research.env`，选择全新私有 `RESEARCH_SERVICE_ROOT`、单独的 `RESEARCH_SERVICE_SOCKET` 目录、已有的授权行情/模型和明确 provider/model。共享令牌用 `secrets.token_urlsafe(32)` 生成，不用示例占位值。
- 模型运行时可选已安装的 Hermes 或 pi。pi 配置 `AUTOMATION_PI_RUNTIME`（安装包目录）、`AUTOMATION_PI_AGENT_DIR`（凭据目录）及 `AUTOMATION_PI_EXTENSION`（仅模型提供方入口），并将其默认 provider/model 明确写入 `RESEARCH_PROVIDER` / `RESEARCH_MODEL`；不会随 pi 默认设置变化而静默换模型。仅直接调用提供方推理，不启动编码会话、不加载技能、个人上下文或工具；每次本地最多等待 240 秒，向运行时请求 6000 输出 token；已安装 pi 的 openai-codex 提供方不会把该上限传给服务端，因此不能把它当作 token 或费用硬上限。pi 固定 SSE、关闭传输重试，无模型调用回退。提供方扩展若注册工具或事件回调则拒绝执行。pi 与 Hermes 的原始调用缓存分开核验。
- 明确授权后，在宿主启动一次 `.venv/bin/python -m a_stock_tracker.research_service`（仅启动接收器，不主动研究），启动前用 `set -a; source .research.env; set +a` 加载宿主环境，勿将此文件传给 Web。默认仅 loopback；配置 socket 时通过私有 Unix socket 通信。此源码不安装 cron、定时或进程管理器。
- 根据 `.research-web.env.example` 配置 `.research-web.env`，仅包含同一桥目录与共享令牌。生产 Web 显式使用 `docker-compose.research.yml` 覆盖文件。已授权部署时可运行 `RESEARCH_WEB_ENABLED=1 ./deploy.sh`；脚本不启动宿主研究进程、不请求行情或模型。首次部署默认不启用该桥；现有容器已有桥时，省略开关会在修改前中止并要求明确选择。
- 服务一次只接受一个执行请求；无队列、无自动恢复、无自动收费重试。进程异常后记录未确认/中断，不能冒充成功；原始产物保留供核查。异常/正常退出均清理工作进程组后才释放执行锁。失败调用保留 `.usage.json`；`usage: null` 表示未知而非零费用，已有调用记录但无合格响应时禁止自动再次调用。基础设施配置/启动/部署不授权任何实际研究请求。

接收器启动时将单文件写入上限设为 32 MB；PDF 提取和模型子进程的 stdout/stderr 合计最多读取 8 MB。每批目录超过 256 MB 则停止（每两秒检查，可能短暂超出），新批次须在研究根目录 2 GB 预算内预留 256 MB；不会自动删除历史产物。持久用户服务模板为 [config/a-stock-tracker-research.service](config/a-stock-tracker-research.service)，适用于项目位于 `~/a-stock-tracker` 的宿主，包含 cgroup 资源隔离与有限异常重启。完整部署流程、systemd 服务生命周期与排障见 [运维与生产部署](#运维与生产部署)。

### 离线性能对照

`make test-mobile` 同时打印合成首屏资源的编码/解码字节数及可操作页面与中文字体加载完成的耗时。只测冷启动、禁用浏览器路由缓存，不代表线上或真机指标。以下命令仅运行首屏测量，不能替代完整点击回归：

```bash
# 同一台空闲机器顺序运行：模拟 10Mbps 下行、1Mbps 上行、80ms 延迟
.venv/bin/python -m tests.test_mobile --performance-only --mobile-network --uncompressed-assets
.venv/bin/python -m tests.test_mobile --performance-only --mobile-network
```

`--uncompressed-assets` 只在合成测试服务中关闭公开资源压缩；省略 `--mobile-network` 可核对 loopback 下的 CPU/压缩开销。比较时同时看传输量和耗时，不把单次结果当成稳定性能预算；真实网络、并发负载和生产反向代理仍需另行验收。

## 波段观察批处理（维护与高级使用）

批处理与 Web 分离；打开页面不请求行情或模型。demo 默认展示明确标记的合成机会与解释，不冒充真实 AI 结果。生产未配置/未发布批次时显示空状态。

真实运行需另行授权，并准备环境中的 `TUSHARE_TOKEN`、已安装的 Hermes runtime 与模型授权；不自动读取 `.worker.env`。还需 TuShare `daily/index_daily/stock_basic/trade_cal` 权限。首次 root 须全新、私有（0700），不要指向个人工作区或旧机器研究目录。

```bash
export AUTOMATION_HERMES_RUNTIME=/absolute/path/to/installed/hermes-agent
# 用最近7天内已完成的交易日替换 YYYY-MM-DD；当日批次须在上海时间18:00以后
# PROVIDER/MODEL 替换为本人已授权的身份；示例不是执行授权
.venv/bin/python -m a_stock_tracker.opportunities \
  --root /private/swing --codes 600519.SH,600900.SH --as-of YYYY-MM-DD \
  --provider PROVIDER --model MODEL --request-budget 20 --seconds 3000
```

每次调用最多 50 次行情请求、3600 秒，最多 5 家、10 次模型调用；生成/复核分别计数，每次本地最多等待 240 秒，请求 6000 输出 token（pi openai-codex 不下传此上限，不能保证硬限制）。默认请求预算 20、时间 3000 秒；没有隐式重试或 resume，重新运行会产生新批次与新费用。生成失败或语义复核未通过不展示价格条件。退出码 0 表示没有证据/模型缺口（可零入选），2 表示至少一家为资料或解读缺口，1 表示整次运行异常；单家不支持或缺资料的公司记为缺口，不丢弃其他公司；不代表策略有效。

当前透明规则（工程起点，未验证投资收益）：

- 61 个完整交易日日线，收盘价 > 20日均价 > 60日均价，近20日价格涨幅强于沪深300；缺日线、停牌零量、身份冲突、名称含 ST/退 或除权造成价格基准不连续均拒绝。名称筛查不等于已核查全部退市风险。
- 观察区间下沿为最近20日最高价加0.01元，上沿为下沿的1.02倍；后续完整日收盘在区间内、成交量至少为批次20日均量的1.5倍，才值得重新评估，**不是买入指令或已触发信号**。
- 近10日最低价为失效条件；区间上沿到失效价距离超过8%不入选。距离不是最大损失承诺；T+1、跳空、停牌和涨跌停可能阻止退出。
- 条件观察有效期为后续5个交易日，不等于持有期；到期后主区域和展开依据均隐藏触发/失效条件及距离，历史解释与量价依据仍可查，原始批次不改写。盘中信号、自动触发追踪与跨批次变化判断尚未实现。

每个 `swing-*` 目录保存证据、模型请求/响应和结果；发布后不改写旧批次，最后原子切换 `latest.json`。只有最终结果和指针成功落盘才报告成功。Web 用 `OPPORTUNITY_ROOT` 读取同一目录，校验结果哈希、有效期与 actor；生产 Web 只读挂载目录，不持行情/模型凭据，不将报告放入静态资源。

Docker 可选覆盖文件 `docker-compose.opportunities.yml` 提供只读挂载，宿主路径由 `OPPORTUNITY_HOST_ROOT` 指定；目录需预先创建并允许容器运行用户读取。基础 compose 不自动启用；现有 `deploy.sh` 不加载此覆盖文件，后续部署必须显式使用两个 compose 文件且另行授权，不能误称已上线。

## 运维与生产部署

生产环境由三层解耦架构构成：宿主 Nginx 反向代理、Docker 容器化 Web 服务、以及宿主独立的 `systemd` 用户研究服务。三者通过严格的只读权限、凭据隔离与受限 Unix socket 通信。

### 架构组件与凭据隔离

| 组件 | 运行形态 | 网络与通信 | 凭据与配置文件 | 隔离边界与安全要求 |
|---|---|---|---|---|
| **Web 界面** (`web`) | Docker 容器 (`a-stock-tracker-web`) | 监听宿主 `127.0.0.1:8550`；仅接受已验证的 Host 与 WS Origin | `.web.env`（GitHub OAuth、白名单用户 ID） | 无行情/模型凭据，不打开业务数据库，只读挂载机会目录；缺配置拒绝启动 |
| **研究网关桥**（可选） | Docker 挂载 (`docker-compose.research.yml`) | 仅挂载专用私有 Unix socket 目录（只读） | `.research-web.env`（socket 路径与共享令牌） | 仅转发经用户显式确认的研究请求，无法读取宿主模型/行情凭据 |
| **宿主研究服务** (`research_service`) | 宿主 systemd 用户单元 | 私有 Unix socket（目录权限 `0700`），仅监听本地 | `.research.env`（TuShare Token、模型运行时凭据、私有根目录） | 持有凭据执行有界子进程，绝不进入 Docker 镜像或挂载给 Web；单次执行互斥 |
| **反向代理** (`nginx`) | 宿主 Nginx | 暴露 80/443，反向代理至 `127.0.0.1:8550` | `docker/nginx-stock.conf`（HTTPS 证书、静态资产 gzip/ETag） | 阻断非法 Host 与外部直接访问容器端口 |

所有环境变量模板见 `.web.env.example`、`.research-web.env.example` 和 `.research.env.example`。敏感配置文件权限须设为 `0600`，宿主数据根目录设为 `0700`，禁止提交至 Git。

### 生产 Web 部署流程（deploy.sh）

部署需在当前会话**明确授权**。`deploy.sh` 具有线上副作用，严禁用作本地日常开发验证。

```bash
# 首次或已有无桥容器的基础只读 Web 部署
./deploy.sh

# 启用网页研究网关的 Web 部署（需先配置 .research-web.env 与宿主接收器）
RESEARCH_WEB_ENABLED=1 ./deploy.sh

# 明确停用已有 Web 研究桥（不停止宿主接收器、不删除研究数据）
RESEARCH_WEB_ENABLED=0 ./deploy.sh
```

开关只接受 `0` 或 `1`，空值及其他写法均拒绝。省略开关时，脚本检查现有 Web（含已停止容器）的研究环境项与桥挂载；发现已有桥则在构建、重建或修改 Nginx 前中止，要求显式选择 `1` 保留或 `0` 停用。Docker 状态读取失败也中止；不会仅因 `.research-web.env` 存在就自动启用。

**部署脚本自动执行的防护步骤：**
1. **配置预检**：检查 `.web.env`、`docker-compose.yml`、Nginx 源配置及目标站点；若启用桥接则核验 `.research-web.env` 与 `docker-compose.research.yml`；
2. **语法与回归**：运行 `docker compose config --quiet` 验证编排语法，执行 `make check` 确保 100% 测试通过且类型/格式干净；
3. **镜像构建与容器重构**：构建 `web` 镜像并执行 `up -d --no-deps --force-recreate --remove-orphans`（自动移除已退役的旧 worker 容器，不删除宿主卷或数据）；
4. **本地健康探针**：以生产 Host 轮询探测 `http://127.0.0.1:8550/`（最多 10 次，每次间隔 2 秒），失败则中断并保留日志；启用桥时，再从新 Web 容器以现有令牌和 socket 只读请求 `GET /info`，核对认证与桥响应；不打印令牌或响应、不启动研究或调用行情/模型。探针失败不会修改/重载 Nginx 或报告部署成功，但 Web 此时已重建，须修复宿主接收器/桥配置后显式启用重部署；该探针仅证明桥可达，不证明市场/模型凭据有效或真实研究可成功；
5. **Nginx 配置平滑切换**：自动备份原配置为 `$site.bak.<时间戳>.<PID>`，写入新配置并执行 `docker exec nginx nginx -t`。校验失败自动恢复备份；通过后执行 `docker exec nginx nginx -s reload`；
6. **外网回环探针**：探测 `https://stock.keyi.win/`（最多 5 次），确认容器持续运行且重启计数为 0。

### 宿主研究服务运维（systemd 用户单元）

持久用户服务模板位于 [config/a-stock-tracker-research.service](config/a-stock-tracker-research.service)，适用于项目位于 `~/a-stock-tracker` 的宿主。

#### 安装与常驻配置
```bash
# 1. 复制单元模板至用户 systemd 目录
mkdir -p ~/.config/systemd/user
cp config/a-stock-tracker-research.service ~/.config/systemd/user/

# 2. 启用用户 linger（确保用户登出或未登录时，后台服务仍持续运行）
loginctl enable-linger "$USER"

# 3. 重载并立即启动服务
systemctl --user daemon-reload
systemctl --user enable --now a-stock-tracker-research.service
```

#### 生命周期管理
```bash
# 查看服务运行状态
systemctl --user status a-stock-tracker-research.service

# 查看实时跟踪日志
journalctl --user -u a-stock-tracker-research.service -f

# 临时停止服务（注意：手动停止不会触发自动重启）
systemctl --user stop a-stock-tracker-research.service

# 重新启动服务
systemctl --user restart a-stock-tracker-research.service

# 彻底停用开机自启并停止
systemctl --user disable --now a-stock-tracker-research.service
```

#### 资源限制与故障恢复
- **cgroup 硬限制**：由单元文件设置 `MemoryMax=1G`、`CPUQuota=100%`、`TasksMax=64`，覆盖包含所有研究子进程；普通 Python 启动不会自动获得这些限制；
- **异常重启策略**：服务异常退出后等待 10 秒重启，5 分钟内最多重启 3 次（`StartLimitBurst=3`）。**重启仅恢复请求接收器监听**，不自动恢复、重试或新建研究批次；
- **进程组安全清理**：停止或异常退出时通过 `KillMode=control-group` 清理全部子进程组，超时 90 秒后硬清理（`TimeoutStopSec=90`），释放执行锁。

- **文件与输出限制**：单文件写入上限 32 MB，PDF 提取与模型子进程 stdout/stderr 合计最多读取 8 MB；
- **磁盘巡检命令**：
  ```bash
  # 检查研究请求总占用
  du -sh /path/to/research-root/*
  # 检查日历与缓存数据占用
  du -sh data/*
  ```


  ```bash

  ```
- **Socket 桥接连通性排查**：
  若 Web 提示“未配置研究服务”，核对：
  1. 宿主接收器服务是否处于 active 状态：`systemctl --user status a-stock-tracker-research.service`；
  2. 桥接目录权限是否为 `0700`，且仅包含目标 socket 文件（无符号链接或杂乱文件）；
  3. `docker-compose.research.yml` 中挂载的 socket 路径与宿主 `.research.env` 中 `RESEARCH_SERVICE_SOCKET` 是否完全一致。

### 运维安全红线与历史隔离

遵循 [AGENTS.md](AGENTS.md) 约束：
- **明确授权原则**：代码修改、命令示例与测试通过均不构成生产操作授权。提交、推送、部署、重启、定时/投递启停及历史数据归档/删除，均须当前会话明确授权；
- **数据不可动原则**：历史数据库（`tracker.db` / `tushare-primary.db`）、笔记、不可变事实 JSON、历史日志与备份原样保留在宿主目录，不挂载给 Web，禁止线上迁移、重算或删除；
- **凭据零泄露原则**：所有凭据与私钥不得进入 Git、Docker 镜像或静态资源包；
- **容器与计划任务**：部署脚本仅按需清理已退役的旧 worker 容器，不得删除宿主卷或宿主数据；源码退役不等于生产容器或系统 cron 已自动停用，已安装定时任务须另行核验与授权停用。

## 自动选股与机器研究（独立批处理）

网页门槛对应的 CLI 是 `--pb-mv-screen --max-research 0`，新批次与续跑均须带此标志；不带标志的命令保留原始全市场/样本规则。以下命令仅为示例，不构成真实请求授权。

不自动读取账户配置或 `.worker.env`。需要环境中的 `TUSHARE_TOKEN`、现有模型授权、已安装的 Hermes runtime，以及 `pdfinfo/pdftotext`。以下是真实请求示例，不是执行授权；运行前须确认累计请求预算、模型身份及费用边界。

```bash
export AUTOMATION_HERMES_RUNTIME=/absolute/path/to/installed/hermes-agent
# 显式小样本验收；仍枚举全市场，财务覆盖永远 partial，累计最多研究 1 家
.venv/bin/python -m a_stock_tracker.automation --root /private/market-research --sample 600519.SH,600900.SH,600019.SH --request-budget 100 --seconds 600 --max-research 1

# 全市场只扫描：不请求公告或模型
.venv/bin/python -m a_stock_tracker.automation --root /private/market-research --request-budget 4000 --seconds 14400 --max-research 0

# 恢复同一冻结批次；显式重设本次预算，批次累计最多研究 1 家
# 不改范围、日期或模型，超过 7 天拒绝恢复；预算不足时保留检查点
.venv/bin/python -m a_stock_tracker.automation --root /private/market-research --resume RUN_ID --request-budget 100 --seconds 600 --max-research 1
```

- 首次 root 必须为空且私有（0700），拒绝符号链接及其他已有数据；不要指向 `data/research`。不读取/写入个人笔记、已阅、持仓、`set-analysis` 或业务数据库。
- 逐证券记录 qualified/excluded/gap/pending 并核对总数。未启用前置门槛时，全市场模式只有完整行业组发布候选、不按总市值截取同业；启用后仅代表筛后池，同样要求该池行业资料完整。在相同估值日、行业、三年年报窗口内复用 PB/ROE 平均名次。每组最多前三，行业轮转，批次队列最多 5 家；不是跨行业投资总榜。抽样模式按输入顺序研究合格样本，不要求行业组完整，也不代表正式筛选结果。
- 默认请求预算 4000、时间 14400 秒、最多研究 5 家；支持范围分别为 3–10000、60–21600 秒、0–5 家。**请求/时间预算按每次调用重新计，恢复不代表批次总预算不变**；`--max-research` 是该批次累计报告数上限，包含已提交的失败报告，不是“本次再加 N 家”。恢复时可显式调整此上限；已有 1 家报告时设为 1 不再生成新报告。行情/公告请求失败最多重试一次。
- 默认模型为 `openai-codex / gpt-6-astra`，可显式传 `--provider` / `--model`，恢复必须与冻结值一致。每个冻结批次累计最多 10 次模型调用，每次本地等待 240 秒，并请求 6000 输出 token（pi openai-codex 不保证此硬上限）；生成与复核分别计数，失败或被终止的调用也计数。调用上限不是费用上限，未报告费用不能写成免费。
- 巨潮定期公告分页，冻结公告列表、PDF 哈希及逐页文本。报告年/期仍限前六页，证券代码须为原文连续完整数字。简称/代码后移时，仅允许第 7–16 页同页唯一的正式简称、代码、公司中文名称字段；简称/代码须与公告一致，公司名称完整值须在前六页同一页与对应年/期组成标题（同一行或相邻非空行），不是正文子串或其他公司名称的前缀/后缀。字段最多 64 个空白/冒号，中文名称整行最多 80 字符；冲突、前缀值、跨页拼接及全文宽松查找不接受。漏页拒绝原文，短页/空白页保守记 incomplete；证据包受字符预算限制，未送入模型的页码必须公开。重大临时公告、诉讼、新闻未全面覆盖，不能声称通读全部资料。
- `scripts/automation_model.py` 只运行无工具推理、返回固定 JSON。证券、页码、数字/单位和逐字引文先程序校验，再另一次模型调用复核语义；未通过不发布确定结论。原文/模型输出不具备命令或个人状态写入权限。
- `summary.md` 是批次入口，`report-代码.md` 展示判断、估值假设、反证、下一步及缺口；先发布/校验报告，再提交候选状态与游标。相同证据/模型/模板不重复推理。
- CLI JSON 与 `invocation.json` 的 `report_counts` / `failed_reports` 区分报告状态与复核失败。退出码 0 要求覆盖完成、无待研究且复核通过；2 表示部分完成或存在失败；运行异常为 1。只扫描也会因候选待研究返回 2。已提交的失败报告是终态，`--resume` 不重跑；修复原因后须显式新建批次。通过复核不代表全文完整、投资可用或获得 `a-stock-qa` 标签。
- 代码交付不启用周度定时或投递。一次性验收不等于生产切换；未来确认预算、时间和目的地后，原生定时器调用同一入口即可。

## 当前阶段与下一步

**当前已按用户反馈将默认页面转向波段机会，但首版只完成有界量价观察与 AI 解释，不等于完整智能荐股。** 旧工作台验收不再是主产品目标。源码落地不等于已部署，也不证明策略有效。

首版验收标准：

- 明示显式股票池与资料日期，不把未入选、资料/解读失败、无批次和观察过期混为同一种“无机会”；允许零观察。
- 每条有效观察能核对解释、反证、尚待核查事项、程序计算的重新评估/失效条件及有效期；模型不能补缺口或生成价格。
- 解释或复核失败不展示价格条件；到期隐藏可行动条件；未核对后续行情时不宣称已触发或仍未失效。
- 手机尺寸下无需命令行、笔记、关注或已阅即可完成选择目标 → 成本确认 → 研究 → 进度/结果 → 条件与反证 → 核查依据 → 返回/退出；结果保持只读，授权与迟到结果隔离不退化。

这些标准检验信息是否可信、可理解、可核查，不证明筛选有投资优势。源码验收使用 `make check` 和 `make test-mobile`：规则、批次完整性、授权/迟到回调与旧路由拒绝均用合成数据/模拟接口；浏览器在 loopback 下验证 360/390/430px 的列表 → 条件/反证 → 依据 → 账户 → 返回/退出，并验证旧 URL 返回 404。它们不替代真实行情、真实模型解释、本人 OAuth 或手机真机验收。生产版本须另核对运行容器与线上入口；发布代码不自动启用真实研究批处理或定时。

| 方向 | 当前状态 | 还缺什么 |
|---|---|---|
| 默认体验 | 网页研究闭环与只读机会列表；旧工作台与兼容入口仍不恢复 | 本人手机验收与已授权生产服务接通 |
| 研究链 | 显式小池、完整日线、透明价格条件、两次模型调用与私有发布 | 有预算的真实小样本核验；板块/公告/催化与财务风险证据 |
| 持续使用 | 网页最近请求与结果重开、到期提示；不消费历史个人工作台 | 跨批次重要变化、条件触发/失效追踪；不恢复个人关注工作台 |
| 运行 | 独立研究接收器与可选私有 socket 桥；CLI 为维护入口；不安装定时或投递 | 明确授权后部署；现存生产容器、cron 与投递状态需另行核验 |
| 投资价值 | 未证明 | 不用可读性、引用通过或技术规则通过冒充收益验证 |

下一步：

1. **先验收连接与异常恢复**：桥目录已在启动时拒绝与研究产物混用及含非 socket 文件，部署时仍须核对实际挂载。报价已明确拒绝与受理未知仍待分别处理，前者应可刷新报价重新确认，后者继续核对原编号；当前可返回入口重新加载报价。用 loopback demo 验收选择目标 → 确认 → 进度/结果 → 解释/条件/反证 → 最近请求重开；确认不需要终端、笔记或已阅，并理解请求结果与首页批次是不同入口。
2. **再验收真实证据链**：另行确认股票池、已完成交易日、模型身份、累计请求与费用边界后，运行一次独立小样本；逐条核对日线、价格条件、解释与最强反证。真实采集、模型复核和本人可读性分别验收，任何一项通过都不代替另外两项。
3. **通过首版验收后再定增量范围**：初筛按尚需采集的股票数优先补齐没有已知缺口的行业；每轮确认新增预算后可继续未覆盖部分。部分覆盖没有候选不能解释为全市场没有机会；行业优先顺序不是投资价值排序。候选池发现、板块/公告催化与财务风险证据、跨批次条件变化均是目标缺口，不是本轮已承诺功能。先选一个有明确来源、失败处理与验收标准的最小增量，再决定是否扩大股票池或接入持续跟踪；不把财报前三直接接成波段推荐。
4. **运行与效果另行验收**：刷新频率、累计预算、部署及定时/投递需单独授权；投资价值需另行设计前瞻观察与评价口径，不能用报告数量、模型复核通过或页面可读性替代。当前不恢复收益回测工程。

旧版本的生产与全市场财报研究验收属于历史记录，见 [CHANGELOG](CHANGELOG.md)；不能替代新波段流程的真实验收。
