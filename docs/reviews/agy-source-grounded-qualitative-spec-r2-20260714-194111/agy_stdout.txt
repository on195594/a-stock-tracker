2. **输入证据缺失与硬性校验规则冲突 (R1 Blocker 2)**：
   - **解决状态**：已通过分阶段规划（Fixture-first 与 Real shadow 分离）解决。

   - **解决状态**：已降级为生产上线阻塞项 (Production Cutover Blocker)。

4. **应用端 Validator 校验规则在未定义 Evidence ID 时不可行 (R1 Blocker 4)**：
   - **解决状态**：已解决。
   - **说明**：通过在 [Section 6.1](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L170-L179) 引入明确的 **Evidence Taxonomy Registry 表**，为所有 evidence 关联了明确的 `evidence_type`、命名空间、allowed_dimensions、允许的 directness 以及 freshness_policy。这为应用端 [Validator](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L268-L270) 提供了完全可机械匹配的契约结构。

## Important notes
1. **Fixture-first (MILESTONE-002)**：
   - 此阶段必须保持 100% 的离线状态，不得访问实际 `tracker.db`，也不得使用真实 API credentials 访问 Gemini API。
   - `QualitativeContext` 中用于单元测试的 synthetic 证据包必须严格遵循 [Section 6.1](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L170-L179) 的 Taxonomy，覆盖正向通过和各种 status=insufficient_data 负例。
2. **Real shadow (MILESTONE-003 / 004)**：
   - 必须等待单独批准的真实证据 Provider 或带 provenance 的静态证据数据集就绪。
   - 即使真实环境下所有股票由于缺乏新闻或竞争壁垒证据而 100% 返回 `insufficient_data`，也**绝对不得**在 shadow 阶段放宽 [REQ-007~REQ-009](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L212-L219) 规定的机械门槛。
   - Shadow 运行数据必须先采用物理隔离的报告文件（如 JSONL 格式的 evaluations artifact），除非新表结构已获得 SQLite DDL 变更批准。
3. **Production cutover (MILESTONE-005)**：
   - `qualitative_scores` 缓存表升级是上线阶段的唯一技术冲突点。Cutover plan 必须包含 `tracker.db` 的物理备份及 readback 脚本（[REQ-054](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L353-L354)）。
   - 在兼容期内，旧版 pipeline 读取路径（[REQ-030](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L274-L275)）不得被破坏，应根据 [REQ-042](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L307-L308) 的缓存优先级策略优雅退避。

## Safety boundary assessment
修订后的 Spec 维持了清晰的安全红线：
- **存储与预测数据边界**：[REQ-036](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L301-L303) 和 [REQ-055](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L354-L355) 严格禁止在 shadow 阶段向 `predictions` 和 `qualitative_scores` 表写入评分数据，并禁止重写历史 predictions。
- **通知与调度边界**：[REQ-036](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L301-L303) 确保 shadow 逻辑与生产的 Telegram 机器人、定时任务和 alpha 权重脱钩。
- **凭证安全约束**：[REQ-039](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L310-L311) 严格限制了错误状态 `failure_reason` 的日志审计范围，严禁将 API key、headers 或堆栈信息持久化至本地或日志中。
- **依赖性红线**：[REQ-013](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L221) 明确不得引入任何外部 outlines / pydantic 等第三方包，完全复用标准库。

## Requirement and test assessment
- **Taxonomy 与状态模型**：分类法设计非常严密且具备可校验性。各维度评分 status 为 scored 与 insufficient_data，消除了可能导致静默猜分错误的中间状态。
- **年龄与新鲜度计算**：`as_of_date - source_date` 采用明确的自然日差逻辑。针对 ROE 等较长更新周期的财务指标，`max_age_550d`（支持回溯至前年年报并覆盖披露滞后期）的计算在工程实现上也是清晰且内部一致的。如果此数值需进一步业务校准，亦可在代码中以配置字典形式修改，不阻塞 validator 的核心代码设计。
- **Test Matrix**：[Section 8](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L359-L387) 覆盖面广且分类良好。Fixture-first 中设计的 14 个测试点不仅包含了基础的 Happy Path，还全面覆盖了 API timeout/4xx/5xx 的退避重试分支、数据不匹配、以及 shape 溢出断言。
- **AC 与 Milestone 映射**：[Section 11](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L451-L462) 的 11 条验收准则与 [Section 12](file:///home/lin/a-stock-tracker/docs/specs/2026-07-14-source-grounded-structured-qualitative-scoring-spec.md#L468-L527) 的 Milestone 建立了明确的依赖关系，不存在编号断层或孤立指标。
