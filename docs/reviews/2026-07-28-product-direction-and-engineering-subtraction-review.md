# 产品方向澄清与工程减法阶段总结

日期：2026-07-28

状态：reviewed
范围：产品目标、策略证据、生产决策链、研究治理、后续三阶段路线

## 1. 结论

项目的主要目的明确为：

> 建设一个 A 股选股与买入决策支持系统，帮助用户判断“买什么、什么时候买”，以提高获得较高风险调整后收益的概率。

系统不能承诺高收益，也不应把工程门禁、报告完整或模型调用成功解释为投资有效性。后续工作的最高评价标准只有三类：

1. 是否提高选股 alpha 或截面排序能力；
2. 是否改善买入时点、降低错误买入；
3. 是否降低回撤、数据错误或不可逆生产风险。

无法对应上述三类结果的新增工程默认暂停。当前项目应从“治理驱动”切换到“可证伪的收益假设驱动”。

## 2. 当前真实产品形态

当前生产链路为：

```text
固定 35 股 watchlist
  → TuShare 基本面、估值与 QFQ 行情
  → Framework A 绝对评分
  → total_score ≥ 44
  → L3 v2 门禁
  → Telegram 主推/候补
  → 30/60/90 日 outcome 与 benchmark 评估
```

因此系统目前更准确的定位是“固定股票池跟踪、评分和买入提示”，尚不是覆盖 A 股市场的完整选股系统。Phase 7 动态股票池仍未启动。

## 3. 已取得的有效成果

以下基础值得保留：

- TuShare 行情、估值、财务与分红数据已形成生产主链；
- QFQ 日线覆盖、来源纯度、readiness、失败关闭和回滚路径已落地；
- prediction 保存决策时评分与定性输入快照，历史核心评分不可改写；
- daily、outcome-update、Telegram、Sheets 和周度运维已能自然运行；
- Framework B prospective cohort 已按固定事件冻结，不再滚动换绑 latest-A；
- outcome QFQ shadow 已证明未复权标签存在真实偏差；
- 测试、类型检查和结构约束为生产数据安全提供了可靠底座。

这些成果解决的是“数据和系统能否可信运行”，但没有自动证明评分或买点可以带来超额收益。

## 4. 当前核心问题

### 4.1 Framework A 尚未证明有序预测力

`buy_strong=44` 来源于可得分上限校准，不是通过未来收益优化得到的门槛。QFQ 总回报 shadow 修正分红口径后，高分五分位仍没有稳定单调性，超额命中率也没有改善。

在固定 watchlist 股票池效应和评分排序效力拆分完成前，不得调整权重或阈值。否则是在同一个有限样本上继续拟合噪声。等权股票池相对基准的收益差不是统计意义上的 beta；如需讨论 beta，必须基于收益序列单独估计。

### 4.2 L3 v2 更像风险熔断，不是买点模型

生产 `v2.1-no-tech-gate` 只在 `close < MA120 × 0.65` 时拒绝；其余 QFQ 数据正常的股票均通过。早期生产记录 70/70 pass，strong 候选没有被过滤。

在证明其能提高后续收益或降低回撤前，产品语义应降级为“极端下跌风险门禁”，不得宣称已经解决“什么时候买”。

### 4.3 Telegram 存在方向性误导

当前展示层把 `total_score - quant_score` 解释为“择时佳/择时弱”。该差值主要是 moat、market position、sentiment 等定性分，不是择时分。

同时主推虽然由 v2 门禁决定，展示仍先描述旧 `entry_signal` 再追加 v2 标签。用户无法清晰区分公司质量、估值和买点状态。

这是直接影响投资决策的产品语义问题，应优先于新的研究治理功能修复。

### 4.4 outcome 真相仍使用 legacy 口径

历史 QFQ shadow 已证明 legacy outcome 会把分红记作价格下跌，但主 `accuracy-report` 仍读取 legacy outcome。历史记录不应原地改写；未来 outcome 应另行设计版本化总收益口径，并明确 benchmark、交易成本和算法版本。

### 4.5 固定 watchlist 限制了“选股”结论

35 股手工池存在市场暴露、行业集中和选择偏差。即使评分在该池有效，也不能直接外推到 A 股市场；若该池整体跑输，也不能直接归因于评分。

在建设 Phase 7 生产动态池之前，应先用 300–500 股历史截面做离线验证。

### 4.6 缺少完整投资闭环

项目目前重点在买入提示，尚未系统覆盖：

- 仓位和组合约束；
- 最大回撤与风险预算；
- 卖出、止损或失效条件；
- 交易成本、停牌和可交易性；
- 持有期与资金占用。

因此当前只能评价“候选买入后的阶段收益”，不能完整评价用户能否获得高风险调整后回报。

## 5. 工程投入倒挂

只统计生产包：

| 区域 | 约代码行数 | 与当前投资决策的关系 |
|---|---:|---|
| Framework A 评分 | 146 | 直接 |
| signals | 359 | 直接 |
| Telegram | 387 | 直接 |
| accuracy report | 491 | 直接但混入大量控制面内容 |
| outcome shadow + migration | 1,842 | 历史口径审计 |
| qualitative M5 | 4,486 | 发布后研究 |
| qualitative archive M4 | 6,650 | 冻结研究证据 |

另有约 6,385 行 M4 测试。该比例说明项目已经花费更多精力证明研究过程完整，而非验证评分与买点是否产生收益。

## 6. 减法决定

### 6.1 保留并维护

- 生产数据采集、readiness、来源纯度和回滚；
- QFQ 行情缓存；
- Framework A 纯评分函数和 prediction 输入快照；
- daily、outcome-update、Telegram 基础链；
- 核心数据质量、交易日、历史不可改写测试；
- Framework B cohort 自动冻结，但只被动积累自然 outcome。

### 6.2 冻结

- `a_stock_tracker/qualitative/archive_m4/` 及其 sealed identifier；
- M5 当前 fixture-first、授权、pilot、bundle 与 reviewer 工具；
- outcome shadow Phase 1/2/3 已有实现和生产证据；
- 已完成的历史 spec、review 和 runbook。

冻结表示不删除、不迁移、不改变 sealed 相对路径，但不再追加功能，也不作为普通产品迭代的默认依赖。

### 6.3 暂停

- 新的 M4/M5 授权、真实模型 Sprint 和 36 股审计；
- outcome shadow 多 run migration 与阶段 C；
- Framework B 生产化；
- Framework C/D/E/F 实现；
- 新治理格式、新 reviewer、新 seal 或新 authorization 层；
- 任何评分权重和买入阈值调整。

过期授权不得自动续期或复用。若未来恢复研究，必须先说明它将验证哪一个收益假设。

### 6.4 验证分级（2026-07-28 已实施）

验证已按以下方式分层：

- 默认套件：评分、行情、生产 outcome、Telegram 和生产数据合同，普通改动运行；
- 冻结审计套件：M4/M5、outcome shadow 和 sealed artifact，仅在对应文件变化时显式运行；
- Ruff 仍覆盖全仓；冻结实现和证据未删除。

`pyproject.toml` 在收集前按路径排除冻结 pytest，mypy 默认排除相同冻结边界；
`AGENTS.md` 保留了覆盖默认参数的显式复验命令。全量测试基线曾耗时 114.59 秒，并因冻结 M4 artifact
权限断言失败而阻断活动产品改动；分层后此类失败留在冻结审计维护范围内，不再混入日常反馈。

## 7. 建议的局部重构

### 7.1 修正决策展示

2026-07-28 已完成第一步减法：Telegram 不再从定性分推导“择时”，也不再并列展示
历史 L3 v1 与生产 v2。当前文案明确区分：

- 公司质量；
- 当前估值；
- 买点/风险门禁；
- 数据可信度；
- 行动建议。

只展示实际决定主推的 L3 v2，并将其称为“风险门禁”，不称为已验证买点。

### 7.2 拆分报告职责

当前 `accuracy-report` 同时承担策略评价、数据质量、Framework B、Phase 6 和运维状态，建议逐步拆成：

- strategy report：alpha、总收益、IC、分位差、回撤、L3 增益；
- ops status：cache、readiness、cron、来源；
- Framework B report：cohort 和生产化门槛。

### 7.3 统一决策合同

若实施，需要另行批准一个小型决策对象，统一承载：

```text
stock_score
valuation_score
timing_state
risk_state
data_confidence
action
reasons
```

评分、L3 和 Telegram 消费同一语义，避免各层自行解释字段。

### 7.4 版本化未来 outcome

未来 outcome 应明确：

- QFQ 个股总收益；
- total-return benchmark；
- 30/60/90 日算法版本；
- 交易成本假设；
- 实际交易日解析；
- 缺失与停牌语义。

不要求重写历史 prediction，也不要求继续扩展已有 shadow migration。

## 8. 三阶段收敛路线

### 阶段一：证明现有系统是否有效

当前立即执行，生产权重保持不变。

1. 比较 watchlist 等权组合与沪深 300，拆出固定股票池效应；
2. 使用 QFQ 总收益评估 Framework A 30/60/90 日分位；
3. 按 `score_date` 计算截面 Spearman IC 并做时间汇总，同时增加 Q5−Q1 spread、最大回撤和样本去重；
4. 报告 L3 v2 的 `NULL/0/1`、状态分布及通过/拒绝后的收益与回撤；若拒绝样本长期接近零，直接判定当前规则无实质选择性；
5. 修正 Telegram 的择时语义；
6. 设计未来 outcome version，但不原地改写历史。

退出条件：

- 明确判断 Framework A 是否具有跨窗口、跨时间批次的正排序能力；
- 明确判断 L3 是买点信号、风险门禁还是无效规则；
- 策略报告使用可解释的总收益口径；
- 在结论前不调整权重。

### 阶段二：离线扩大股票宇宙并验证框架

阶段一形成可复验基线后启动，不直接建设生产动态池。

1. 构建 300–500 股历史截面研究集；
2. 做行业分层或行业中性比较；
3. 验证 Framework A/B 在不同市场阶段和行业的 IC、top-bottom spread；
4. 加入交易成本、停牌、可交易性和样本外评估；
5. 若 Framework A 无效，先简化或重做评分，不叠加新框架。

退出条件：

- 完成预先约定的样本外、行业分层、成本和可交易性检验并形成可复验结论；
- 若有框架显示稳定、可解释且不依赖固定 35 股或单一时间区间的排序优势，明确可以
  进入生产候选池的规则和失败边界；
- 若没有框架通过，明确简化、重做或停止，不用叠加新框架延长研究。

### 阶段三：建设生产决策支持闭环

仅在阶段二通过后启动。

1. 建设动态候选池和受控数据采集；
2. 上线经验证的买点信号，而不是仅重命名风险门禁；
3. 增加仓位、组合集中度、退出/失效条件和风险预算；
4. 用小范围 report-only/canary 验证，再逐步影响主推；
5. 持续监控收益、回撤、换手和模型漂移。

退出条件：

- 系统能回答“买什么、为什么现在买、买多少、何时退出”；
- 推荐记录拥有完整决策时快照和事后可归因结果；
- 风险调整后结果优于明确基准，且不是由单一行业、市场暴露或固定股票池效应驱动。

## 9. 防止再次工程过重的约束

1. 新任务先写一个可证伪的收益或风险假设，不默认写新 spec。
2. 只读研究不创建生产级 migration、seal 或授权系统。
3. 只有生产 DB、cron、凭证、真实外部调用、权重和不可逆行为使用重治理。
4. 研究结果不足时限制声明，不用更多工程把“不确定”包装成“完成”。
5. 同类能力优先复用；不得为每个样本、模型或 run 新建一套编排框架。
6. 代码、测试和文档投入应与其对投资决策的贡献成比例。
7. 任何治理机制若不能指出它防止的具体不可逆风险，默认不新增。

## 10. 近期优先级

1. P0：保持 TuShare、daily、outcome 和 cron 自然运行，刷新 stale probe；
2. P1：固定 watchlist 股票池效应与 Framework A 排序能力拆解；
3. P1：修正 Telegram 决策语义，补 L3 v2 效果报告；
4. P1：规划未来版本化 QFQ outcome；
5. P2：被动等待 Framework B cohort 自然结案；
6. HOLD：M4/M5、shadow stage C、多框架生产化和 Phase 7 生产实现。
