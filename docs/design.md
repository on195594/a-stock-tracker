## Problem Statement

当前 a-stock-research 是一个 Claude Code skill（SKILL.md = 278行提示词）。
它能做深度的 A股基本面+技术择时分析，但有三个根本限制：
1. **必须手动触发**：每次分析都要在 Claude Code 里发起对话
2. **分析逻辑是提示词，不是程序**：无法追踪历史预测、无法量化准确率
3. **进化是手动的**：每次改进都要人告诉 Claude 改哪个文件

目标：在不减少任何现有功能的前提下，构建一个能**每天自动运行**、**追踪预测准确率**、并最终**自动调整评分权重**的独立应用。

## What Makes This Cool

- 当前系统分析一只股票得 73 分，但你不知道"73 分"有没有意义
- 改造后，3 个月后系统能告诉你："Framework A 的 ≥55 分预测，30 天跑赢沪深300的概率是 X%"
- 再往后：权重不再是你拍脑袋定的，是数据说了算

## 现有系统架构

```
SKILL.md (提示词) → Claude 解读 → WebSearch + fetcher.py → 分析报告
```

目前已有的可复用组件：
- `fetcher.py`：完整的 AKShare 数据获取，已有 spot_em 当日快照缓存（D0 优化）
- `cache.py`：SQLite 缓存层，支持基本面/分析结论/预警/持仓
- 6个行业框架（A/B/C/D/E/F）+ 格雷厄姆估值 + 防韭菜检查

## Premises

1. 当前 80 分制是定性启发规则，不是在历史数据上训练的模型。回测结论可能是"无显著预测力"。
2. "独立运行"不需要完全脱离 LLM。定量评分（ROE/PE/PB）在本地计算，定性部分（护城河/政策风险/异动）通过 Claude API 完成。
3. 进化引擎有天然延迟：第一批可信信号需要 30-90 天后的价格结果。
4. 最有价值的第一步是打通"记录预测 → 跟踪结果 → 量化准确率"的闭环，而非立即自动修改逻辑。

## Approaches Considered

### Approach A: 预测记录器（最小可行楔）
- 给 cache.db 加 predictions 表，记录每次分析后的预测
- 每天脚本检查价格，记录 30/60/90 天实际涨跌
- 优点：零风险，立即开始
- 缺点：仍需手动触发分析，样本积累极慢
- Completeness: 3/10

### Approach B: 自动管道 + 权重参数化（选定）
见"Recommended Approach"

### Approach C: 闭环自进化引擎（长期终态）
- 在 B 的基础上加 optimizer.py，自动拟合权重
- 依赖 B 积累的 50-100 个结案结果
- 当前阶段不构建，但架构为其预留接口

## Recommended Approach

**Approach B：自动管道 + 权重参数化**

### Phase 1 范围限定（已完成）

Phase 1 只做一件事：**证明闭环可以跑通**。

- 只实现 **Framework A（通用）**。等 50+ 结案记录后再扩展 B/C/D/E/F。
- **不调用 LLM** 做自动化评分。定性维度（护城河/政策风险）在 Phase 1 中固定为默认值，避免非确定性污染数据。
- **不推企业微信**。Phase 1 输出本地 text 文件（`accuracy_report.txt`），手动查看。
- **不创建 optimizer.py**。等 Phase 4 再动。

**⚠️ Phase 3 已于 2026-04-26 提前上线**，将部分 Phase 2/3 功能合并为一个阶段实施（见下方 Phase 3 说明）。

### 整体架构（Phase 1）

```
【一次性初始化】
pipeline.py init
    └── 对 config.WATCHLIST 每只股票调用 lib/fetcher.py fetch <code>
        → 填充 tracker.db 的 stock_fundamentals 表
        → 后续 cmd_batch 才能有效运行

【每日运行】
cron job（每日 16:30 盘后）
    ↓
pipeline.py daily
    ├── 启动检查：计算今日 weights_hash；若今日已有记录但 hash 不同 → 警告并退出
    ├── lib/fetcher.py batch → 更新 stock_fundamentals（含 report_period、最新价）
    ├── 对每只 WATCHLIST 股票：
    │   ├── cache.get_fundamentals(code) → 提取 data 字段字典
    │   ├── price_at_score = spot_em 快照["最新价"]（批量抓取后过滤，无需额外 API）
    │   ├── scorer.score_stock(code, "A", data) → 定量评分
    │   └── INSERT OR IGNORE → predictions 表（含 report_period / weights_hash）
    └── 追加 daily_log.txt（审计用）

cron job（每日 17:00，daily 完成后留出 30 min 缓冲）
    ↓
pipeline.py outcome-update
    ├── 拉取沪深300历史价格 → index_prices 表（已有日期跳过，无重复 API 调用）
    ├── 查询 predictions 表中 score_date + 30/60/90 自然日 ≤ 今日的未填记录
    ├── 用今日 spot_em 快照价格计算 outcome（涨跌幅%，非绝对价格）
    ├── 若当日无交易数据：向前找最近 5 交易日可用价（estimate_flag=1）；超出则 NULL
    └── 写入 outcome_*d + benchmark_*d（benchmark 失败则仅写 outcome，benchmark 留 NULL）

pipeline.py accuracy-report
    └── 输出：按评分阈值分类的命中率（绝对 + 超额 benchmark，多窗口）
        → 统计显著性警告：≤100 条记录时明确标注"样本不足，结论仅供参考"
```

**outcome 单位规范：**
- `outcome_30d` = `(price_at_outcome / price_at_score - 1) * 100`，单位为百分比（如 +5.2、-3.1）
- `benchmark_30d` = 沪深300同期涨跌幅%，取法相同
- `alpha_30d` = `outcome_30d - benchmark_30d`（SQLite 生成列，两者相减有意义）

### scorer.py 函数契约

```python
def score_stock(code: str, framework: str, data: dict[str, float | None],
                weights: dict | None = None) -> dict:
    """
    Args:
        code:      股票代码，例如 "601288"
        framework: "A"（Phase 1 只支持 A）
        data:      从 cache.db 读取的字段字典，值可以为 None（数据缺失）
                   Phase 3 新增：可包含 moat_fixed/market_pos_fixed/sentiment_fixed 键，
                   覆盖 weights.json 中的 phase1_fixed 值（Gemini 注入路径）
        weights:   可选，不传则从 weights.json 读取

    Returns: {
        "quant_score":       float,            # 0-65（满分65，Phase3 Gemini注入后上限约80）
        "total_score":       float,            # quant_score + 定性分
        "component_scores":  dict[str, float], # 各维度得分，调试用
        "missing_fields":    list[str],        # 数据缺失的字段名
        "data_quality":      float,            # 0-1，可用字段比例
    }

    Raises:
        UnsupportedFrameworkError  # framework 不在已实现集合时
        InsufficientDataError      # data_quality < 0.5 时（少于一半字段）
    """
```

**Phase 3 Gemini 注入路径（scorer.py 关键改动）：**
pipeline.py 在调用 `score_stock()` 前，将 `get_qualitative_score()` 的返回值注入 `data` dict：
```python
qual = get_qualitative_score(code, name)   # 返回 {moat, market_pos, sentiment}
data["moat_fixed"]        = qual["moat"]
data["market_pos_fixed"]  = qual["market_pos"]
data["sentiment_fixed"]   = qual["sentiment"]
result = score_stock(code, framework, data, weights)
```
scorer.py 中，`phase1_fixed` 字段的取值逻辑从 `return float(field_cfg["phase1_fixed"])` 改为 `return float(value) if value is not None else float(field_cfg["phase1_fixed"])`，从而允许运行时覆盖。

### 缺失数据处理规则

| 字段缺失情况 | 处理方式 |
|-------------|---------|
| 某维度数据为 None | 该维度得 0 分，记入 missing_fields |
| 缺失字段 ≥ 50% | 抛出 InsufficientDataError，该股票跳过，记入 pipeline 日志 |
| PE 历史分位无法计算（上市 < 1 年）| 估值维度得 0 分，标注 data_quality 下降 |

### weights.json 结构（Phase 1，仅 Framework A）

**评分结构改为 breakpoints + 线性插值，消除断崖效应。**

**Breakpoints 语义：**
- 每个 breakpoint 是 `[metric_value, score]` 对，按 metric_value 升序排列
- 两点之间线性插值
- 低于最小值时取最小 score，高于最大值时取最大 score（不外推）
- `invert: true` 的字段（debt_ratio / pe_percentile_10y）：breakpoints **已经按"值越小，score 越高"排列**，解释器对所有字段执行相同的线性插值逻辑，**无需对输入值做任何变换**。`invert` 标志仅作为语义注释，不影响计算逻辑。

总分结构：**基本面 60 分 + 择时 20 分 = 80 分**

| 类别 | 维度 | 满分 | 数据来源 | Phase 1 处理 |
|------|------|------|---------|------------|
| 基本面 | ROE 近 3 年均值 | 15 | AKShare | breakpoints 线性插值 |
| 基本面 | 净利润增速近 3 年均值 | 10 | AKShare | breakpoints 线性插值 |
| 基本面 | 资产负债率 | 10 | AKShare | breakpoints 线性插值（invert） |
| 基本面 | 毛利率 | 10 | AKShare（待验证） | 自动计算或固定 5 |
| 基本面 | 护城河 | 10 | LLM | Phase 1 固定 **5** |
| 基本面 | 行业地位 | 5 | LLM | Phase 1 固定 **2** |
| 择时 | PE 历史 10 年分位 | 15 | AKShare | breakpoints 线性插值（invert） |
| 择时 | 市场情绪 | 5 | 半定量 | Phase 1 固定 **3** |

Phase 1 实际可计算最高分：约 **70 分**（LLM 维度固定保守值）。
**Phase 3 实际可计算最高分：约 80 分**（Gemini 填入最高定性分时）。

**评分示例（600036 招商银行，Framework A，breakpoints 演示）**：

假设数据：ROE=16.5%, 净利润增速=5.5%, 负债率=91.2%, 毛利率=56.8%, PE分位=18%
```
ROE 16.5%：在 [15,15]→[25,15] 区间，插值结果 = 15 分
净利润增速 5.5%：在 [0,2]→[8,6] 区间，插值 = 2 + (5.5/8)×4 = 4.75 → 4.8 分
负债率 91.2%（invert）：超过 80%，取最低分 = 0 分
毛利率 56.8%：在 [35,10]→[60,10] 区间 = 10 分
护城河 Phase1 固定 → 5 分
行业地位 Phase1 固定 → 2 分
PE 10年分位 18%（invert）：在 [5,15]→[20,12] 区间，插值 = 15 - (13/15)×3 = 12.4 分
情绪 Phase1 固定 → 3 分
total_score ≈ 15+4.8+0+10+5+2+12.4+3 = 52.2 分
```

对比旧版：ROE 14.9% 在旧版得 0 分，新版得 14.85 分——消除了数据小波动导致的断崖跳跃。

### predictions 表结构（修订版）

```sql
CREATE TABLE IF NOT EXISTS predictions (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    code            TEXT    NOT NULL,
    name            TEXT,
    framework       TEXT    NOT NULL,    -- Phase 1 固定为 "A"
    score_date      TEXT    NOT NULL,    -- YYYY-MM-DD
    price_at_score  REAL,
    quant_score     REAL,                -- 定量得分（Python 计算）
    total_score     REAL,                -- Phase 1 = quant_score + fixed_defaults（含护城河5+市场地位2+情绪3）
    weights_hash    TEXT,                -- md5(json.dumps(weights["frameworks"], sort_keys=True))[:8]，只对 frameworks 子树求 hash，避免 updated_at 变化触发虚假实验分组
    report_period   TEXT,                -- 评分时 AKShare 返回的最新财报所属期（按报告期排序取第一条的 report_date 字段，如 "2024-09-30"）
    outcome_30d     REAL,                -- 30 自然日股票涨跌幅%（NULL = 未到期）
    outcome_60d     REAL,
    outcome_90d     REAL,
    benchmark_30d   REAL,                -- 沪深300同期30日涨跌幅%（NULL = 未到期）
    benchmark_60d   REAL,
    benchmark_90d   REAL,
    alpha_30d       REAL GENERATED ALWAYS AS (outcome_30d - benchmark_30d) VIRTUAL,
    alpha_60d       REAL GENERATED ALWAYS AS (outcome_60d - benchmark_60d) VIRTUAL,
    alpha_90d       REAL GENERATED ALWAYS AS (outcome_90d - benchmark_90d) VIRTUAL,
```

### 准确率定义（accuracy-report，修订版）

**⚠️ 统计显著性警告（重要）：20 只股票 × 3 个月 ≈ 60 条 30d 结案记录。这个样本量不具备统计显著性，任何命中率结论都不可信。accuracy-report 头部强制显示此警告，记录数 < 100 时加粗提示"样本不足，结论仅供参考，请勿据此做交易决策"。Phase 1 的目标是数据积累，不是得出结论。**

**⚠️ 选择性偏差免责声明：watchlist 是手动维护的已知标的，不代表全市场。命中率反映的是"你选入 watchlist 的股票在该评分下的表现"，而非"该评分框架的泛化能力"。泛化能力需要无偏样本，Phase 1 无法提供。**

**⚠️ 退市/长停牌股处理：`outcome_*d` 置 NULL 后被 `IS NOT NULL` 过滤，此为预期行为，accuracy-report 头部注明"已排除 N 条 NULL outcome 记录（停牌/退市/数据缺失），见 daily_log.txt"。**

**绝对命中率**（`outcome_30d > 0`）：

```sql
SELECT
    CASE
        WHEN total_score >= 65 THEN 'strong'
        WHEN total_score >= 55 THEN 'moderate'
        WHEN total_score >= 45 THEN 'light'
        ELSE 'no-action'
    END AS signal_tier,
    COUNT(*) AS predictions,
    -- 30日绝对命中率
    ROUND(AVG(CASE WHEN outcome_30d > 0 THEN 1.0 ELSE 0.0 END), 3) AS hit_rate_30d_abs,
    -- 30日超额命中率（跑赢沪深300）
    ROUND(AVG(CASE WHEN alpha_30d > 0 THEN 1.0 ELSE 0.0 END), 3) AS hit_rate_30d_vs_300,
    -- 60日超额命中率
    ROUND(AVG(CASE WHEN alpha_60d > 0 THEN 1.0 ELSE 0.0 END), 3) AS hit_rate_60d_vs_300,
    -- 90日超额命中率
    ROUND(AVG(CASE WHEN alpha_90d > 0 THEN 1.0 ELSE 0.0 END), 3) AS hit_rate_90d_vs_300,
    -- 平均超额收益
    ROUND(AVG(alpha_30d), 2) AS avg_alpha_30d,
    ROUND(AVG(alpha_60d), 2) AS avg_alpha_60d,
    ROUND(AVG(alpha_90d), 2) AS avg_alpha_90d
FROM predictions
WHERE outcome_30d IS NOT NULL    -- 30d 到期才纳入统计
GROUP BY signal_tier
ORDER BY CASE signal_tier
    WHEN 'strong'   THEN 1
    WHEN 'moderate' THEN 2
    WHEN 'light'    THEN 3
    ELSE 4
END;
```

**解读指引（写入 accuracy_report.txt 头部）**：
- `hit_rate_30d_abs` > 50% 仅说明多头市场，不代表框架有效
- `hit_rate_30d_vs_300` > 55% 才开始有意义（超额概率持续跑赢）
- `avg_alpha_30d` > 2% 且样本 ≥ 20 条，可认为有初步信号
- 不同 `weights_hash` 的记录分开解读，权重变化前后是两个不同实验
- 60d/90d 列在 outcome 未到期时为 NULL，SQLite AVG() 自动忽略 NULL，结果正确（不需要额外 WHERE 过滤）

### 容错机制

| 故障场景 | 处理方式 |
|---------|---------|
| AKShare API 超时 | 指数退避重试 3 次（1s/2s/4s），3 次失败则跳过，记入日志 |
| 沪深300 benchmark 拉取失败 | 先尝试东方财富，失败后自动降级腾讯 fallback；两者均失败则 benchmark_*d 置 NULL，不影响 outcome |
| 某只股票 InsufficientDataError | 跳过，记录到 `skipped_stocks` 日志，不中断整体 pipeline |
| 当日 weights_hash 与已有记录不符 | pipeline.py daily 启动时检查，不同则警告并退出（不覆盖旧数据）；需手动确认后删除当日记录再重跑 |
| outcome 到期日无交易数据 | 向前找最近 5 个交易日内的可用价格（`estimate_flag=1`）；超出 5 日则置 NULL（`estimate_flag=0`） |
| spot_em 批量快照失败 | 自动降级为腾讯日线逐股获取（`stock_zh_a_hist_tx`，5日窗口取最新收盘价）；两级均失败则 price_at_score 置 NULL |
| Gemini API 失败/超时/未配置 | all-or-nothing fallback：三个定性字段全部使用 phase1_fixed 值（moat=5, market_pos=2, sentiment=3） |
| Gemini 字段值越界 | `_validate()` 拒绝，触发 all-or-nothing fallback，不混用部分 Gemini 值 |
| Telegram 推送失败 | 记 WARNING 日志，不阻断 daily 流程（Telegram 是展示层，SQLite 是真相来源） |
| 股票停牌/退市 | outcome 字段置 NULL，accuracy-report 自动排除，report 头部注明排除条数 |
| pipeline 崩溃中途 | 已写入 predictions 表的记录不回滚；UNIQUE 约束保证重跑幂等（INSERT OR IGNORE） |
| .env 未配置 API Key | `_load_dotenv()` 在模块级调用，cron 环境不需额外设置；无 Key 时 Gemini/Telegram 静默跳过 |
