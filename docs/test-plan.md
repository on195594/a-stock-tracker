## Key Interactions to Verify

### a_stock_tracker/scoring.py
- Breakpoints linear interpolation produces correct values between anchor points
- Boundary: metric at exactly a breakpoint value
- Boundary: metric below min breakpoint → min score (no negative scores)
- Boundary: metric above max breakpoint → max score (no over-scoring)
- Invert field (pb_percentile_10y): lower % → higher score
- None fields → score=0, recorded in missing_fields, data_quality reduced
- data_quality = available non-fixed fields / 5 (non-fixed total)
- **Phase 3：** moat_fixed/market_pos_fixed/sentiment_fixed 在 data dict 中有值时优先使用（Gemini override）；None 时回退 phase1_fixed

### a_stock_tracker/integrations/gemini_scorer.py（Phase 3 + Batch B 更新）
- 正常路径：API 返回合法 JSON → `_validate()` 通过 → 写缓存 → 返回 dict
- all-or-nothing fallback：任何字段不合法 → 全部返回 FALLBACK（不混用）
- 超时/异常：`_call_gemini` 返回 None → `get_qualitative_score` 先尝试过期缓存，无缓存时返回 FALLBACK dict
- 缓存命中：30天内有记录 → `_call_gemini` 不被调用
- 值域验证：moat 1-10，market_pos 1-5，sentiment 1-5，必须为整数
- 无 API key：静默返回 None（不 raise），触发过期缓存降级或 FALLBACK
- Markdown 代码块包装（```json...```）：自动去除，正常解析
- **Batch B 新增：** retry backoff — 429/5xx 时退避重试最多 3 次（间隔 2s/4s）；401/403/解析错误不重试
- **Batch B 新增：** stale cache fallback — Gemini 失败后先尝试 `_check_cache_stale()` 返回最新过期缓存，无缓存才用 FALLBACK

### a_stock_tracker/cli.py daily
- After batch fetch, INSERT OR IGNORE is truly idempotent (re-run = no duplicate rows)
- weights_hash computed from `frameworks` subtree only (not updated_at or version fields)
- price_at_score extracted from spot_em snapshot `最新价` field by stock code
- report_period extracted from cache JSON `report_period` field
- **Phase 3：** spot_em 失败 → 腾讯日线 fallback（`stock_zh_a_hist_tx`）；两级均失败 → price_at_score=NULL
- **Phase 3：** Gemini 注入前必须 copy data dict（避免污染 fundamentals 缓存对象）
- **Batch A 新增：** per-stock SAVEPOINT 隔离 — 每只股票用 `SAVEPOINT sp_stock` 包裹；崩溃时只回滚该股，不影响已成功的 stock；重跑幂等

### a_stock_tracker/cli.py cmd_init / cmd_weekly（Batch A 新增）
- cmd_init 委托 `_build_watchlist()` + `bulk_cache()`；测试验证调用次数 = watchlist 长度
- cmd_weekly 委托 `_run_weekly_fetch()`；测试用 mock 断言 fetcher 被调用且不发真实网络请求

### a_stock_tracker/cli.py outcome-update（Batch B 更新）
- outcome_30d = `(outcome_price / price_at_score - 1) * 100` (percentage, not absolute)
- estimate_flag=1 when using nearest available price (within 5 trading days)
- estimate_flag stays 1 on re-run (idempotent: CASE WHEN ? = 1 THEN 1 ELSE estimate_flag)
- outcome NULL when no trading data within 5 days of target date
- benchmark_30d failure → outcome written normally, benchmark_30d left NULL
- benchmark requires both score_date and target_date prices; one missing → NULL
- 60d/90d outcomes not overwritten if not yet due

### a_stock_tracker/cli.py accuracy-report
- Output order: strong → moderate → light → no-action
- No division-by-zero when count=0 for a tier
- stat warning displayed when total closed records < 100
- exclusion count printed in header (NULL outcome rows excluded)

### a_stock_tracker/data/fetcher.py spot_em retry（Batch B 新增）
- 单次失败不锁定今日（fail_count=1 < MAX=3），下次调用仍重试
- 连续 3 次失败 → `_spot_em_failed_today = today`，后续同日调用立即返回 ERROR
- 日期切换后（today ≠ _spot_em_failed_today）：计数器重置，允许重试
- 成功后：`_spot_em_fail_count = 0`，但 `_spot_em_failed_today` 不清除（保留今日锁记录直到日期切换）

### a_stock_tracker/data/cache.py _ensure_columns allowlist（Batch B 新增）
- 合法列名 `[A-Za-z_][A-Za-z0-9_]*` → 允许 ALTER TABLE
- 非法列名（含空格/注入字符）→ `raise ValueError("unsafe column name")`，不执行 SQL

### a_stock_tracker/integrations/agent_reviewer.py Gemini（Batch B 新增）
- 正常路径：Gemini 返回合法 JSON → `validate_review_output()` 通过 → 返回 ReviewOutput
- 任何错误（网络/解析/validate 失败）→ `_fake_review_fallback` 降级
- 429/5xx retry：最多 3 次，不重试 401/403
- 直接 `TimeoutError/socket.timeout` 与 `URLError(timeout)`：最多 3 次，2s/4s 退避；第三次成功返回真实 review
- timeout 三次耗尽后 fallback；非 timeout `URLError`、401/403、解析错误均只调用一次并立即 fallback
- `validate_review_output()` 拒绝 forbidden keys → 不写入

### cron wrapper / installer
- wrapper 接受 `<command> [label] [--alert-exit-2]`，label 与 option 顺序可交换
- duplicate option、duplicate label、unknown option 在执行命令前返回 64
- fake crontab 在 HOLD 下识别本项目 `pipeline.py daily` 与 `-m pipeline daily` 变体并规范化为一条 managed daily
- 注释、其他项目任务、行尾注释中提及本项目路径的任务不得触发 preserve 或 cleanup
- 连续安装两次 crontab 字节一致；fake curl 证明 exit 2 告警与默认抑制语义不变
- HOLD + existing daily 输出“保留现有评分链”，不得同时宣称移除；HOLD + no daily 输出“不新增评分写任务”
- rollback 从与快照不同的 fake live crontab 开始，经真实 `--rollback` 入口后必须逐字节恢复快照

### MILESTONE-004 离线审计工具链

- frame 必须精确覆盖 31 个 SW2021 一级行业，Decimal 市值分层和原 seed 抽样保持确定性。
- URL 仅接受批准的官方域，保留 path 大小写和 CNIPA 实质 query，去除限定追踪参数。
- corpus 必须覆盖完整 source × query 矩阵，按冻结 round-robin 顺序并用文号/URL/raw hash 去重。
- technical ledger 的 D/D+1/D+2、pending/blocked 语义不得被转成 insufficient。
- artifact blob/stage 必须 create-only；并发发布不得覆盖，review-index 精确绑定 corpus 与双 seal stage hash。
- Reviewer 默认 preview；execute 需要绑定 bundle/prompt/model/backend/command/environment 的 authorization。
- stdout/stderr/timeout 必须增量限流并清理整个进程组；真实 Codex/AGY/Gemini 和网络在测试中被 autouse fixture 阻断。
- seal、index、adjudication 和 coverage report 必须重新验证 frozen manifest、双 workspace bundle 和全部 label 语义。
- v1.2 capability probe 必须精确执行三调用矩阵，逐调用复验 canonical authorization/hash/clock，禁止重试、分页、额外参数和重定向。
- classification、bulk membership、daily 和 12 个抽样单元分别 fail closed；`complete` 与 `capability_pass` 必须分离。
- probe receipt/blob/manifest 必须 raw-first、内容寻址、create-only、token 扫描且可离线重算；全部 bytes 永久 `non-adoptable`。

## Edge Cases
- Same-day weights.json change: pipeline.py daily detects hash conflict, warns and exits
- `pipeline.py init` on already-populated DB: fetcher handles TTL, no duplicate entries
- Watchlist stock with pb_percentile_10y=None (< 1 year listed): dimension scores 0, data_quality decremented
- All 5 non-fixed fields None: data_quality=0 → InsufficientDataError
- **Phase 3：** Gemini 返回 float（如 7.5）→ `_validate` 拒绝，触发 FALLBACK
- **Phase 3：** Gemini 返回缺少字段（如只有 moat）→ `_validate` 拒绝，触发 FALLBACK
- **Phase 3：** `_call_gemini` 返回 None（timeout/HTTP error）→ 先尝试过期缓存，无缓存才返回完整 FALLBACK
- **Phase 3：** spot_em 失败但腾讯 fallback 成功 → price_at_score 有值（非 NULL）
- **Batch B：** outcome window 传入非法值（如 "120d"）→ `ValueError`（_OUTCOME_WINDOWS allowlist 拦截）
- **Batch B：** _ensure_columns 传入含分号的列名 → `ValueError`（identifier regex 拦截）
- **Batch B：** spot_em 连续 2 次失败（< MAX=3）→ 不锁定，第 3 次调用仍发起请求
