# 个人同业选股工具：实施 Spec

> 正式 Spec｜2026-09-22｜仅供个人研究。对齐[个人选股能力推进路线图](../plans/2026-09-22-personal-stock-selection-roadmap.md)。
> 本文与路线图共同构成本项目当前的正式选股工具文档。同业发现、候选审查和显式快照对比均已于2026-09-22实现；本人已确认第二次交付判断，监管门和部分股息输入不完整时仍保持 fail-closed。实现完成不代表投资效果已验证，也不授权恢复 Framework A。

## 1. 本轮做什么，做到哪里就能用

**输入一家原关注池中的非金融公司，发现池外同业，按盈利能力与估值做比较，帮助本人决定下一家研究谁。**不再以“重新排列原 35 股”作为首次产品交付。

| 交付 | 必须产出的结果 | 完成标志 |
|---|---|---|
| 1．同业发现 | 参照公司、真实池外同业、逐年 ROE、同日 PB、同业内前三与参照位置 | 至少一家池外公司取得合格数据并参与比较；不要求池外公司进入前三 |
| 2．候选审查 | 前三名的排序原因、与参照公司的指标差异、事实与待核查问题 | 本人能据此作出一次“继续研究／暂不研究”的判断，理由写在已有笔记中 |
| 3．变化跟踪 | 两次快照的候选进出、PB 与逐年 ROE 变化，区分数据／成员／规则变化 | 能定位值得重看的公司；不必重读全部报告 |

第一次即可试用；完成第二次即可作为个人工具保留。第三次后续按需补，不阻塞使用。不设新审批、研究日志系统、预算平台或长周期阶段闸门。

不做：买卖点、收益承诺、历史回测、自动调权、账户交易、全市场扫描、新数据库、迁移、批次仓库、发布平台、LLM、网站、通知和定时任务。这些不自动进入后续待办。

    .venv/               复用其已有 Python 环境

`screen.py` 按 `load_reference → load_peers → load_inputs → rank_peers → render_report` 实现；变化跟踪复用同一快照并由 `compare_snapshots` 完成。不为每个函数建模块、工厂或框架。用标准库和现有依赖；确有重复才提取函数。

旧库只通过 SQLite `mode=ro` 的显式读连接访问。原关注集合从 `config.py` 的 WATCHLIST 字面量解析取得，不执行整个旧模块；不导入旧 CLI，不调用带初始化行为的 `get_db()`。不修改旧 WATCHLIST、分数、manifest、预测表、报告或 cron，也不把翻修旧 writer 作为前置工作。

凭据只从既有受支持的凭据读取方式或环境取得，不复制到新目录、不写日志和快照。独立 Git 仓库已初始化并连接公开远端 `on195594/a-stock-screen`，`.gitignore` 排除 `output/`、凭据和本地缓存。原库和旧输出不是新工具的写入目标。

## 3. 范围与数据：先找同业，再取财务

### 3.1 参照公司＋至多 49 家同业

参照输入使用带交易所的代码，必须在保存的原关注集合中。按本次基础信息确认其为当前沪深主板非金融公司；行业不明或不适用就明确提示，不猜行业、不临时换公式。金融排除使用一小段明确的提供方行业标签映射，不开发行业分类平台。

按同一提供方行业标签枚举当前沪深主板同业。先保留参照公司；其余对象按**同一数据日的有限正总市值降序**取至多 49 家，同值按代码。之后缺 PB、缺财务或不符合候选资格，不以第 50 家及以后补位。参照公司即使缺数据，也保留一行说明，但不伪造排名。

这是有市值偏向、最多 50 家的粗粒度同业比较，不保证主营业务完全可比。旧 35 股只用于参照选择与“旧池／池外”标记，不限制新同业数据接入。

基础枚举不完整、行业范围无法确认或疑似接口截断时，明确失败，不输出声称完整的同业前三。个别公司的数据缺失单列，不阻塞其他合格对象。

### 3.2 只需要这些输入

| 输入 | 用途与最小来源 |
|---|---|
| 代码、名称、行业、市场、交易所、上市状态 | 确认参照与同业范围；已有明确来源的基础信息，或显式刷新 `stock_basic` |
| PB、总市值及所属交易日 | PB 比较和范围截取；已有同日估值，或显式刷新 `daily_basic` |
| 三份年报的 `roe_waa`、期末日、公告日及版本依据 | 重新计算三年均值；已有原始财务，或对截取后公司逐股刷新 `fina_indicator` |

以上接口选择沿用路线图，不保证实际账户具备权限。已有数据合格就复用；不足且给出 `--refresh` 才联网。所有选择的来源、源日期和取得时间写进本次快照；不把不同日期的 PB 拼成同日，不把某个均值当作三份年报。

财务请求只针对本次最多 50 家，先查所需近年年报；权限失败直接说明缺口，不换供应商或购买权限。请求需有超时且不得无限重试。只处理所需年份；返回疑似截断则补取必要范围或记录缺失，不默认为完整。

无权限时，可读一份有来源、符合本规范字段的本人导出 JSON，不建设通用 CSV 适配器。人工导出若缺完整同业枚举和范围依据，只展示已提供事实，不宣称完成同业发现交付。

### 3.3 日期、缺失与修订

本工具只做**当前资料比较和已有快照复看**，不提供历史时点回测。

一次清单只有一个 `data_date`，即 PB／市值的数据日。默认使用已有资料能够确认的最近已完成交易日；无法确定则提示传 `--date`，不能只按周一至周五猜交易日。指定日无数据时列缺口，不默默换日。财务可用性按原次实际筛选时间判断；较早的 `--date` 只选估值日，不证明财务在当日已经可得，报告须明确两种时间。

ROE 逐年保存百分数值、年度、报告期和公告日期。需要最近已披露的连续三个完整年度，每年一个可确认版本；不能跳过缺失年份、拿季度凑年数、把缺失值跳过后仍称三年均值。同一年度先去除精确重复行；有且仅有一条 `update_flag=1` 的修订记录时采用该记录，没有修订记录且只有一条原始记录时采用原始记录；其余多版本冲突单列并排除，不任取最后一行。当前使用后来披露的修订值，不倒称过去已知。快照保存所选 `update_flag` 和选择依据。

最新年度期末距 `data_date` 超过 550 个自然日，不参与排序。财报期晚于估值日的输入不与该估值日组合排名；公告晚于原次实际筛选时间的输入拒绝。只有公告日期而无时刻时保留日期精度，不虚构时分秒。550 天沿用路线图，是运行限制，不是投资最优参数。

PB／总市值保留提供方单位，ROE 固定为百分数；PB 无单位、ROE 差值用百分点、市值只在一致单位下排序。数值必须有限，布尔、NaN、无穷、空串和 null 均不能冒充正常值。核心来源无法确认的公司只展示事实或缺口，不参与正式排序。

风险警示采用首版可执行规则：同次 `stock_basic` 返回的当前名称去空白并转大写后，以 `ST` 或 `*ST` 开头即视为已知风险警示，不进入候选；名称缺失或其他风险状态未核验时写“风险状态待核查”，仍可参与比较，不要求先买专门接口。快照保存原始名称、判断结果和来源。报告固定注明：非实时资料；风险警示、停牌与可交易性未完整核查；没有发现风险不等于没有风险。

## 4. 唯一规则：peer-screen-v1

候选必须具备完整、日期与来源合格的三份年报和同日 PB，**三年 ROE 均值 > 0，PB > 0**，且没有按第 3.3 节规则识别出的风险警示。某一年 ROE 为负但三年均值仍为正，可以参与，并在报告提示该事实；三年均值非正则排除，负均值不参与排名。

```text
roe_mean = 三个年度 roe_waa 的简单平均
roe_rank = roe_mean 在共同合格同业中从高到低的平均名次
pb_rank  = PB 在同一共同合格同业中从低到高的平均名次
research_order = (roe_rank + pb_rank) / 2
```

同值取平均名次；按 `research_order` 升序、代码升序确定最终位置。计算不使用展示舍入值。参照公司若合格，与同业一起排名；若不合格，仅展示其事实和原因。展示最多前三，参照若已在前三不重复，否则单列。少于三家展示实际数量；仅一家时写“事实展示”，不称“筛选胜出”。

不生成跨行业总榜，不恢复 Framework A 或 `buy_strong`，不搜索权重或阈值。排名只是研究顺序，不是买入分、低估结论或上涨概率。

## 5. 报告、快照与变化

### 5.1 第一、二次交付的输出

报告头部写参照公司、行业／范围限制、估值日、采用年报年份、实际筛选时间和来源；覆盖写“枚举／截取／合格／缺失”，附成员排除原因。表格至少有：公司、旧池／池外、逐年 ROE 与均值、PB、两项名次、研究次序。报告后附完整结果与缺口。

第二次交付只增加前三名的短说明：为什么排名靠前；相对参照的 ROE 均值差（百分点）与 PB 差（候选 PB 减参照 PB，单位为倍）；最新年度 ROE 下降、某年负值、采用年度不同等已知事实；主营可比性、杠杆／一次性损益、资产质量及交易风险等固定待核查问题。

参照数据不合格就不计算该项差值；年报年度不一致明确标注，不把差额说成严格同口径优势。“PB 较低”不改写成“被低估”；固定核查问题不伪装成已发现风险。本人结论保留在现有笔记，不开发录入功能。

`snapshot.json` 用普通 dict/list，只保存复看所需内容，不引入模型库或数据注册：

| 顶层字段 | 保存什么 |
|---|---|
| `schema_version`、`rule` | 简单格式号 1、`peer-screen-v1`、公式与 cap=50/top_n=3/550天限制 |
| `screened_at`、`generated_at`、`data_date` | 原次实际筛选时间、本次文件生成时间、PB／市值日期；时间带时区 |
| `anchor`、`watchlist_codes`、`scope` | 参照代码、当次原关注集合、行业来源与日期、枚举成员、截取成员及理由 |
| `rows` | 各公司基础信息与原始名称、PB／市值及日期、三年逐项 ROE／报告期／公告日／`update_flag` 与版本选择依据、实际来源与取得时间、风险判断及排除原因 |
| `results` | 合格集合、各项名次、最终次序、前三和参照位置；允许导入文件初次为空，由相同规则计算 |

不要只保存前三或一个均值，否则无法复看和解释成员变化。重放保持 `screened_at`、`data_date` 和原输入不变，只更新文件生成时间；不读取现场数据。不支持的规则只展示已有结果并说明未重算。旧快照若缺逐年 ROE、同业范围等信息，只能展示事实，不能自动升级、补造字段或声称完成本轮筛选。

每次新建唯一输出目录；先保存快照，再写临时报告并替换为 `report.md`。失败明确报错，不留一份伪装完成的最终报告；不覆盖输入、旧目录或旧报告，不维护 latest 指针，也不建设跨文件发布机制。

### 5.2 第三次交付：显式快照对比

`--compare` 读取本人指定旧快照。先比较参照、行业来源／范围规则和排序规则；不兼容就只展示原始事实差异，注明不能比较排名。规则相同但成员不同，可展示进出与指标变化，但明确标记成员影响。

只突出前三进出、PB 变化、逐年 ROE／年报更新。前次候选本次缺数据或未进入截取范围，应分别写“本次缺失／范围变化”，不写成经营恶化；PB 变化不得直接归因于股价。同一输入不产生新变化。首次无对比文件就省略这一栏。

## 6. 命令与开发顺序

以下命令均已可用。从 `a-stock-screen/` 运行。代码仅示例语法，不是股票推荐：

```bash
# 第一次交付：从参照公司发现同业，显式联网补数
../a-stock-tracker/.venv/bin/python screen.py \
  --tracker-root ../a-stock-tracker --anchor 600900.SH --refresh

# 必要时指定估值数据日；不构成历史回测
../a-stock-tracker/.venv/bin/python screen.py \
  --tracker-root ../a-stock-tracker --anchor 600900.SH --date YYYY-MM-DD --refresh

# 离线复看：不依赖旧仓库或提供方，不联网
../a-stock-tracker/.venv/bin/python screen.py --input output/<旧运行>/snapshot.json

# 对比本人指定的旧结果
../a-stock-tracker/.venv/bin/python screen.py \
  --tracker-root ../a-stock-tracker --anchor 600900.SH --refresh \
  --compare output/<旧运行>/snapshot.json

# 完全离线比较两个已保存结果
../a-stock-tracker/.venv/bin/python screen.py \
  --input output/<当前运行>/snapshot.json \
  --compare output/<旧运行>/snapshot.json
```

无 `--refresh` 的参照模式只能用本地已取得且来源完整的数据；数据不足明确报错或列缺口，不将旧 35 股冒充完整同业。`--input` 与刷新／重新指定参照或日期互斥；它不混读旧库。只有 `--refresh` 允许联网。参数错误、范围无法形成或写文件失败返回非零；完整输入经过资格过滤得到零候选可以正常输出，但不等于证明工具有用。

实现已按顺序收口：第一次连接读取、同业补数、排序和表格；第二次只加解释；第三次只加快照对比。三个阶段均未引入新数据库、调度、回测或模型。
