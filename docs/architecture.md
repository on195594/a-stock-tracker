# 研究工作台的模块与数据合同

用户只需回答三件事：接下来研究谁、关注公司变了什么、下一步核查什么。

```text
config/anchors.json ──→ 发现候选 ──→ 我的研究 ←── 指定公司代码
TuShare ──→ 独立 worker ──→ 不可变事实快照 ──→ 变化 / 已阅 / 下一步
交易日历证据 ──→ 提交时冻结目标日             ↑
                                   私人 SQLite 工作区
```

| 模块 | 职责 |
|---|---|
| `config.py` / `paths.py` | 本项目参照 JSON、工作区与数据目录 |
| `calendar.py` | 独立日历采集、来源证据、完整性/覆盖/原子发布、最近已证明交易日 |
| `research.py` | 同业枚举、严格年度 ROE 选择、PB/ROE 排序及本次事实采集 |
| `watch.py` | 冻结个人关注或指定单公司的事实更新；不重筛，不改变历史同业名次 |
| `evidence.py` | 最新已披露报告选择、完整/部分报告校验、安全展示、日期倒退判断与核查提示 |
| `workspace.py` | 三表、schema/模式、快照导入和持久化安全 |
| `services.py` | 鉴权后的研究查询/写入、事实比较、任务受理 |
| `worker.py` | 独立任务执行、请求/快照身份验证、发布与故障恢复 |
| `app.py` / `auth.py` | Flet 页面、会话、OAuth/ASGI 边界 |
| `maintenance.py` / `manage.py` | 初始化、合成 demo、导入、离线备份/恢复 |

研究采集不读取原 tracker.db 或财报观测库、不执行旧 Python 配置、不用旧缓存冒充本次核查。没有旧评分、QFQ、收益基准或通用财务物化链。日历是研究流程仍需要的唯一周期维护。

## 行为合同

- 同业发现保持 peer-screen-v1：沪深主板非金融、TuShare 粗行业、按市值最多 50 家，PB 升序/三年 ROE 均值降序名次取平均，并列取平均名次，展示前三和参照。行业标签不证明业务可比；排序不等于买入评分。
- 财务要求连续三份年度、明确证券身份/公告日期/修订选择；重复、截断、非有限值及版本冲突都必须显式处理。发现扫描可按资格跳过财务请求，固定关注更新逐家公司重新核查；实际采集不沿用旧财务，取得时间不能冒充公告日。
- 我的研究优先呈现异常、公司风险状态和财报变化；PB、日期与来源范围变化折叠，仍可完整对照但不计入首页待处理数量。仅核查时间变化不算财务变化。公司页先显示自己的判断、支持/反对证据和下一步，再显示事实对照、财报原文入口与历史排序依据。
- 单公司与关注更新复用一次 `fina_indicator` 请求，新增营收/归母/扣非归母同比、资产负债率、每股经营现金流。`research_report` 为不可变事实 JSON 的可选扩展，选择本次取得且已公告的最新报告期；唯一修订标记优先，缺失与版本冲突不回退。新报告有缺口不能已阅，旧快照缺少扩展保持兼容并明确提示。原 peer-screen-v1 排名及历史快照不变，不跨快照拼接完整资料。
- 关注无需笔记；保存笔记不推进已阅。已阅独立显示，必须再次验证实际显示快照、最新失败、日期与 revision/updated_at。未关注、损坏、缺口、过期版本或撤销授权不能越过这些校验。
- 更新冻结提交时的目标日与范围；同 ID 不同意图拒绝，同范围在途合并。单公司沿用 `kind=watch`，意图为 `{"kind":"watch","code":"600900.SH"}`，范围必须恰好为该代码；批量关注仍为 `{"kind":"watch"}`。提交及 worker 验证证券范围，生产指定公司须为正常上市的沪深主板非金融公司。获取资料不自动关注；暂停只阻止批量更新，不阻止本人明确更新一家公司的请求。
- worker 在网络访问前释放数据库事务，关页面不取消任务；结果固定路径、不可覆盖、哈希与任务身份一致才能登记。页面内只读轮询进度，不重新提交；完成后保留当前页面和输入，提供结果入口，由本人点击进入。切页、退出、撤权及断线后的迟到结果均受会话与页面版本校验。
- 登记快照前同步文件及工作区内的各级父目录；同步失败不登记成功。崩溃恢复再次执行同步与身份检查，不能仅以文件存在判断成功。
- 三张业务表 `screen_runs`、`watch_items`、`update_jobs` 保留 schema 名称以兼容旧研究记录。它们不是旧行情库；历史快照的 `source=tracker` 及规则身份也不改写。
- 同业发现的失败/partial 与上次完整榜分开，不用部分结果生成新的正式前三。公司详情可使用经过验证的 partial 快照中该公司的可用事实；已阅仍按该公司的缺口、损坏、日期、较新失败和版本逐项校验。公司更新失败时，最新财报区和研究提示显示本次失败，旧资料只在历史事实区供参考，不能自动换已阅基准。完整与部分财报均校验字段结构、来源和日期，公告日不得晚于取得日（上海日期）；异常指标不展示。年度 ROE 提示按报告期排序。暂停不删除笔记，恢复不重新排名。

## 运行与验证

一个 Web、一个串行 worker、一个独立日历命令。Web 只有 OAuth 配置；worker/日历只有行情凭据。Web 只读挂载整个日历目录，原子更新后能读到新文件；私人研究目录不经静态服务暴露。

测试保留原研究数据、鉴权、冲突、任务恢复、日历失败回滚的反例，并验证不需要相邻项目。浏览器覆盖空工作区扫描→关注→保存→已阅、按代码研究、单公司范围、财报证据、断线重连、迟到结果及 360/390/430px 手机宽度。真实接口、本人 OAuth、手机与备份恢复需单独验收，不能用离线绿灯替代。正式迁移仅在需要切换工作区时执行；当前阶段和推进顺序以 [README](../README.md#当前阶段与下一步) 为入口。
