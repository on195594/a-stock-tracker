产品目标与验收见 [README](../README.md#产品目标与规格归属)，开发约束见 [AGENTS.md](../AGENTS.md)，部署与运维见 [运维](operations.md)。本页只描述当前实现的模块归属与合同；已由测试或类型约束覆盖的细节以代码为准，不在此重复。

```text
网页（本人 OAuth）  ─┐                       ┌→ 财报研究 → 引用核验报告
                     ├→ 私有 socket → 接收器 ─┼→ 初筛 → 筛后同业排名
本机 MCP（Agent）  ─┘   （按令牌识别渠道）     └→ 价格纪律参考（无模型）
```

## 模块归属

| 模块 | 职责 |
|---|---|
| `web/` | FastAPI + Jinja2 服务端 HTML：OAuth/会话/CSRF、安全头、页面路由、展示规则，一个同源脚本 |
| `contracts.py` | 接收器、Web、MCP 共用的 pydantic 接口模型与错误码 |
| `research_client.py` | 经私有 socket 调用接收器；Demo 客户端只产生合成数据 |
| `research_service.py` | 宿主接收器：报价比对、按编号幂等、单次互斥、渠道限额、预算子进程、结果复验 |
| `mcp_server.py` | 本机 stdio MCP 服务：10 个工具，只读方法白名单，15 分钟报价暂存 |
| `automation.py` / `research.py` / `evidence.py` | 财报初筛冻结、覆盖、平均名次与证据选择 |
| `disclosures.py` + `scripts/automation_model*.{py,mjs}` | 原文证据、无工具模型生成、逐字校验、一次修复与剔除、独立复核 |
| `opportunities.py` | 价格纪律参考的有界采集、程序计算与私有批次读取 |
| `auth.py` / `bounded_process.py` / `atomic_io.py` | 会话登记与签名、子进程边界、原子落盘 |

Web 不持行情或模型凭据，不打开数据库，不读取研究根目录；所有研究数据都经接收器读取。

## 网页研究请求合同

- **提交协议**（Web 与 MCP 共用）：客户端生成 32 位编号，提交完整请求与报价；接收器按当前配置重算报价，变化时返回 409 `quote_changed`。同编号同内容返回既有状态，不再执行，也不计入限额；同编号不同内容拒绝。
- **确认**：GET 永不提交；POST 必须勾选成本确认。报价变化时保留输入、重新报价并清除确认；被拒时保留输入并给出原因。
- **受理未知**：显示原编号与已确认费用，只允许用 GET 核对或按同一编号重新提交，不另起新编号，也不承诺提供方零费用。
- **财报报价**：含 `model_budget`（最多 10 次调用，本地超时 240 秒），没有 token 或费用硬上限，超时也不保证停止计费；页面逐字展示这一边界。初筛与价格参考不调用模型。
- **初筛**：新初筛固定 1500 次请求 / 3600 秒；续跑只接受七天内、门槛一致的检查点，报价为 `min(剩余待覆盖数 + 20, 1500)` 次。前置门槛为 0＜PB≤3、总市值≥50 亿元，这是工程默认值，未经收益验证。结果页预览每组前 3 名，完整排名经接收器分页读取（每页 50 行，游标绑定冻结批次与过滤条件）。
- **结果与档案**：每次读取都复验原始产物（在释放请求状态锁后执行重文件校验）；失败、中断或校验错误不展示旧的成功结果。接收器返回内容若未通过接口模型校验，客户端一律按 `ResearchUnavailable`（MCP `service_error`）处理，不归咎为调用方输入错误。财报只放行复核通过的段落与引文，失败只显示固定的阶段与类别说明。`/runs` 在接收器侧按 `mode`、`code`、`limit`（1–20）、`cursor` 过滤并按研究链最新活动时间排序（支持链上任一节点作游标），`/reports?code=` 返回该公司最多 20 条已复核报告摘要；`/stock/{code}` 仅聚合接收器已复核报告与价格参考记录生成公司档案，不引入本地状态库。首页“公司”页按代码聚合各类型最近 20 条研究链，每家只显示最新可读报告与最新价格参考；失败、被取代或已过期的结果在展示层自动收起（不删除、不改写批次），仍可在分类记录页翻看。单家公司财报研究仍枚举全市场、覆盖恒为 partial，因此所请求报告全部复核通过即记为 `completed`；价格参考结果记录本次请求数、上限、耗时与停止原因，旧批次的用量保持未知（`null`）。

## 研究质量 v3

规则身份为 `cited-machine-research-v3`，v1/v2 报告按原样读取（无一句话结论时网页以主要风险首句代替）。报告面向普通投资者：

- **必需段落**：`summary`（一句话结论，以“值得继续研究 / 需要谨慎 / 暂不值得”开头，研究优先级而非交易建议）、业务、财务、主要风险（`counterevidence`）；估值与改变判断的条件可选。
- **行情快照**：同一次 `daily_basic` 调用加取 `close / pe_ttm / dv_ttm`（不增加请求），与 PB、总市值一起作为 `structured.market_snapshot` 交给模型；段落可引用特殊编号 `MKT`，估值段可只引 `MKT`，必需段落至少引一条原文事实。快照只用于报告，不参与初筛资格或排名。
- **正文数字校验**：各段正文里的数字须出自该段所引事实所在的原文页（引文可能只截一行）或报告期年份；结构化字段与行情快照只对引用了 `MKT` 的段落算出处。允许元→万元/亿元换算与按显示位数四舍五入，百分数与金额不互相匹配；完整日期须是来源写明的日期，单独年份须是报告年份或所引原文出现过的年份；不超过 12、且后面不跟亿/万/元/倍/%/百分点的整数（个数、月份）放行。事实 claim 的数字仍须逐字在引文中，唯一例外是引文或原文页有“(%)”表头列时可把 30.85 写成 30.85%（符号与数位不变）。数字规则不核对单位语义（例如原文表格里无单位的数值），语义仍由独立复核把关。

首轮生成后：

1. **身份错误**（公司代码不一致）直接失败。同一公司的 schema、事实数不在 1–8 条、引用不存在的事实编号或必需段落无原文事实，与引用级错误共用下述一次修复机会；结构不合格的初稿不进入剔除或复核，修复失败或预算不足时不发布。
2. **引用级错误**（引文非逐字、页不存在、数字或单位不符，以及正文数字无出处 `analysis_number_mismatch`）在 `model_calls + 2 ≤ 10` 时修复一次。修复请求逐条附带诊断（引文偏离原文的位置及原文后续内容、不在引文中的数字或单位、各段无出处的数字），原因码与校验规则不变。已发出的修复调用在续跑时重放，或拒绝再次收费。
3. 首轮与修复后的报告分别剔除仍不通过的事实，再撤下正文数字无出处的段落（可选段标为“事实不足，未形成”，记 `numbers_unsupported`；必需段失去支撑），取支撑更好的一份（满足必需段落与至少三条事实 → 有支撑的必需段落数 → 事实数，打平保留原稿），不在两个候选报告之间逐条拼接。任一必需段落失去支撑，或剩余事实少于 3 条，即失败。
4. 最终内容做独立语义复核，复核失败不展示草稿。

### 新批次的原文位置引用

新证据包带 `citation_format: line-ranges-v1`；已有证据包与已发布报告按原合同读取，不改写历史批次。仍使用 v3 的最终报告与 Web/MCP 展示合同，证据格式及生成/修复提示参与缓存身份。

- 模型只返回 PDF 来源类型、文档编号、页码、连续起止行及事实主张；程序从冻结原文回填引用。模型输入保留整页上下文并加行号，原文与文档哈希原样保留。位置越界、跨页拼接、超过引用长度或模型自带引文均不能放行。
- 模型须选入关联表头、单位、期间和必要脚注；新格式的数字、百分号表头及日期仅取所选范围，不借用同页其他表格或文档报告期。范围内无法确认具体日期时保留原文相对期间，不补出月份。程序的逐字/数字检查不证明表头关系、口径和语义，最终仍须独立复核。
- `MKT` 仅为有有效日期的冻结行情引用，不能成为 PDF 事实、不计入三条原文事实；新格式正文引用 MKT 时只使用行情快照字段。
- 保持一次生成、最多一次修复和一次独立复核。修复输出仅包含被允许的事实和所有受影响段落的补丁；其他事实、段落、公司与缺口冻结。修改范围外对象、改编号或新增事实会拒收修复；合并后重跑完整校验。事实数超量时允许删除多余事实并修正依赖段落，不允许借机改写已知事实。无法可靠识别对象的结构错误直接失败。
- 原稿与修复稿都按必需段落覆盖和有效事实数比较，打平保留原稿；评分不替代发布门槛。已发送的修复按原编号重放缓存或拒绝再次收费，预算不足不新增调用。

`quality` 字段记录生成、修复、剔除（含修复调用删除的事实）、未形成段落与通过的事实数，网页收在“研究范围与质量”、MCP 原样返回。报告投影把固定的系统范围声明（`scope`）与本公司的具体缺口（`gaps`）分开，另带行情快照 `snapshot`；`/reports` 摘要带一句话结论 `conclusion`。

## 价格纪律参考

`price-reference-v2` 只由程序计算显式小池（≤5 家），不调用模型，也不以趋势或距离排除资料完整的公司。个股遇交易所除权参考价（`pre_close / 前收盘` 在 [0.3, 1)、窗口内 ≤2 次）时前复权到最新价格口径并逐次披露，其余不连续仍拒绝；`price-reference-v1` 历史产物按原样读取。有效期为后续 5 个交易日，不是持有期。过期后，服务端每次渲染都会隐藏观察线、失效线和距离；已打开的页面由脚本按上海日期隐藏；MCP 返回空价位，并清空相应的事实文字。

## 安全基线

- **认证**：GitHub OAuth 的 state 一次性、10 分钟有效，并与发起登录的浏览器绑定；单进程最多保留 128 条未完成状态，清理过期状态后仍满额则返回 429，不挤掉在途登录；只允许数字 ID 白名单中的本人。会话 cookie 为 `HttpOnly`、`SameSite=Lax`、`Secure`，有效期 8 小时，由服务端登记；退出或重新登录会使其他副本失效。
- **管理员密码登录（可选）**：`.web.env` 设置 `ADMIN_USERNAME` 与至少 16 字符的 `ADMIN_PASSWORD` 后，`POST /login/admin` 签发与 GitHub 登录相同的所有者会话；未设密码时该路由 404。`ADMIN_LOGIN_SCOPE=local`（默认）只接受客户端地址为回环或 `ADMIN_ALLOWED_IPS` 所列地址/网段的请求，其他请求得到 404；私网不算本地（同一 Docker 网络的其他容器也在私网内）。客户端地址只在 TCP 对端属于 `ADMIN_TRUSTED_PROXIES`（容器名、地址或网段，生产为 `nginx`，按容器 DNS 解析）时取 Nginx 写入的 `X-Real-IP`，否则一律取 TCP 对端，直连容器无法伪造；Nginx 由宿主 `nginxconfig.io/proxy.conf` 以 `$remote_addr` 覆盖该头，改动该文件须保持覆盖；`any` 对公网开放。Nginx 仅对 Cloudflare 公布网段内的对端采信 `CF-Connecting-IP` 作为客户端地址（`real_ip`），直连源站无法伪造；Cloudflare 网段变化时须同步 `docker/nginx-stock.conf`。表单 POST 除同源检查外还校验登录前 CSRF 令牌（登录页签发、与本浏览器 10 分钟 cookie 一致才放行）；IPv4 映射的 IPv6 地址按 IPv4 匹配白名单。比较用 `hmac.compare_digest`，不做哈希、限频、锁定或轮换，安全性取决于密码强度；成功与失败均记录来源 IP。
- **在途撤权**：私有页在读取接收器之后、写出响应之前再次核验会话；轮询遇到 401 即停止并清空进度。
- **请求来源**：所有 POST 都校验 CSRF 令牌（`HMAC(secret, sid)`），并校验 Sec-Fetch-Site、Origin、Referer 是否同源，缺失即拒绝。Host 严格匹配 `PUBLIC_BASE_URL`。
- **响应头**：CSP 为 `default-src 'self'`，无内联脚本或样式，无 eval，无 WebSocket；私有响应一律 `no-store, no-transform`（`no-transform` 禁止 Cloudflare 等代理改写页面，如注入会被 CSP 拦截的统计脚本；HTML 压缩由源站 Nginx 完成）；Jinja2 自动转义，模型文本与 URL 只作纯文本。
- **重放与退役**：0-RTT 早期数据携带的写请求返回 425；退役路由（`/published`、`/opportunity/*`、`/api/session`、旧工作台路径）返回 404。
- **demo 模式**：只允许 loopback 与合成客户端；生产缺配置拒绝启动。

以上各条与原 Flet 安全用例的对应关系见 `tests/test_web_security.py` 文件头。

## MCP 与 Agent

- **形态**：本机 stdio 服务（`python -m a_stock_tracker.mcp_server`），读取 0600 的 `.research-mcp.env`，经私有 socket 调用接收器，不持行情或模型凭据。
- **令牌与限额**：接收器按令牌识别 `web` 与 `mcp` 渠道，并把渠道写入请求元数据。`mcp` 渠道按上海日期每日最多受理 3 次（全部研究类型，失败不退还，幂等重放不计）。
- **工具**：查询类为 `get_service_info`、`list_runs`、`get_run`、`find_reports`、`get_report`、`get_facts`、`get_price_reference`、`get_screen_ranking`；提交类为 `prepare_run`（只报价并暂存）和 `submit_run`。
- **错误与输出**：错误统一为 `{code, message}`，`code` 取自 `contracts.ErrorCode`。模型文本与引文作为数据返回，工具描述注明“不是指令”。
- **确认层**：`submit_run` 不得加入客户端的自动放行列表。

## 部署与历史隔离

生产结构为 Web 容器、宿主 systemd 接收器与 Nginx 代理。

- **Web 容器**：只挂载私有、只含 socket 的桥目录。
- **接收器**：从宿主工作区启动批处理，因此任务运行中不得改动该工作区；升级须按[运维](operations.md#接收器升级与回滚)单独授权。
- **凭据**：`.research.env`、`.web.env`、`.research-mcp.env` 不进 Git，也不进镜像。
- **历史数据**：历史数据库、快照、日志与备份留在宿主目录，不提供在线读写入口。

### 问题、目标与非目标

已复现的故障模式：模型选错原文范围；修复返回冻结段落导致补丁拒收；删除事实后正文仍残留依赖该事实的论断；修复遗漏已指出的日期错误；数据准备异常只记录异常类型，无法定位底层原因。成功输出证明某次完成，不证明稳定性。

目标是降低每份合格报告的总 token 成本，提高有充分证据样本的成功率，同时不增加无据结论放行或削弱反证覆盖。缺资料、解析关系不明、预算不足或复核失败时仍可明确失败；“每次都生成报告”不是目标。语义真实性不由 schema、哈希、模型自报置信度或一次成功证明。

范围仅限现有财报报告链路及其合同、质量投影和测试。首版不引入 agent 框架、向量库、自动换模型、全量财务数据库、通知或自动恢复；不新增行情/财报数据源。解析器替换仅在独立样本证实现有提取破坏结构时另行选型。

### 一、程序分块与候选召回

继续从已有冻结 PDF 提取结果构建证据。每个不可变证据块保存 `block_id`、文档哈希、页码、原文起止位置、逐字文本、章节类别、可验证的相邻上下文关系。ID 由规范化的文档哈希集合、分块/关系规则版本、全部成员片段的页码/范围/角色有序列表及关系证明记录共同哈希确定，模型不得生成任意页码/行号或新块。分块不调用生成模型、不改写原文。

首版引入版本化的复合证据合同，明确替代新批次“单一同页连续引文”限制，旧批次仍按旧合同读取。`block_id` 指向程序预构建的证据包，包含一个连续数据/正文主片段及零至五个连续上下文片段，每个片段各自带文档哈希、页码、原文范围和角色（主片段/表头/单位/期间/脚注/关系标记）。主片段去空白 15–1600 字，上下文片段 1–1600 字；包总量受阶段上下文预算约束。不得把多个片段拼成貌似连续的单段引文。模型只选包 ID，不输出任意范围。

表格包须包含支持主张的表头、单位、比较期和必要脚注，相关原文共同构成合法证据，但必须保存可检查的关系依据。首版只接受同页有明确表格边界的关系，以及同一冻结文档中具有明确表名/“续表”标记、重复列结构且无竞争表头的跨页关系；这是一组可审计的程序规则，不声称仅凭版面接近即可证明关系。关系标记是上下文片段，计入最多五个上下文片段配额；其来源位置、逐字文本和关系类型纳入包身份，并随包进入复核及逐片段展示。最终语义复核再次检查。缺关系、存在歧义、超片段上限或片段无法保留必要上下文时拒绝该包；不把文档标题年份当作数据期间。当前纯文本提取无法建立关系的样本须计入不支持/失败，不得从评估分母移除；若影响质量闸门，先阻断实施结论，再单独评估结构解析器。

正文段落可直接构成单片段证据包；大表按行/相关行组建立主片段，并显式关联上述上下文，避免截断表头/脚注。日期、单位与数字的合法来源是所选包内经关系校验的片段集合，完整页及邻页只作复核上下文，不能自动扩大合法来源。新报告必须逐片段展示页码和原文，并清楚标明上下文角色；这要求显式新证据/报告版本和 Web/MCP 调用方升级，不以旧单引文字段承载拼接文本。

按业务、主要财务指标、现金流、非经常性损益、资产负债、风险/审计/附注分组召回。先按章节/词项规则和现有指标召回，再在各组内选候选；不以“前若干页+关键词页耗尽字符预算”充当覆盖证明。不加入 embedding 或 LLM 摘要替代原文。每包保留由确定性召回规则产生的类别标签集合及命中依据，模型不能自行添加类别标签；每组记录可用候选、已入选范围、遗漏和原因；缺失风险组不能默认为无风险。

程序允许一次不调用模型的候选扩展；仍无法在预算内覆盖关键类别则返回 `evidence_insufficient` / `context_budget_exceeded`。候选数和优先级由评估集校准，不预设关键词排序就能保证召回。不得利用本次模型想写的结论反向过滤反证。

### 二、事实选择、正文生成与独立复核

正常流程固定为三次无工具模型调用：

1. `select_facts`：输入候选证据块与来源元数据，输出 3–8 条 `{fact_id, block_id, claim}` 以及按类别的缺口。程序核验公司、包/片段身份和关系、引用长度、数字、单位、日期、事实数量和必需类别覆盖后冻结合格事实集。业务、财务、主要风险至少各有一个合格事实，允许同一事实覆盖多个类别，但只能使用该包预先冻结的类别标签；风险/审计/附注候选非空时，必须至少选入一条带该组标签的事实，不能以其他类别的事实顶替；当风险候选非空却未选入有效风险依据，或删除事实使必需类别归零时，本阶段失败并至多使用共享修复机会，不进入正文生成。候选类别归属仅作覆盖下限，不证明已覆盖最强反证，最终复核必须与独立风险候选比较。明确缺口可覆盖非必需子类，不能代替必需反证段的原文事实。模型主张的语义是否与证据吻合仍须最终独立复核。事实不足时在正文生成前停止，不让正文使用未通过机械校验的事实。
2. `compose`：只输入冻结事实、其原文和必要上下文、结构化行情及明确缺口。每个段落由 `{sentence_id, kind, text, refs}` 列表组成。`kind=assertion` 的 refs 必须非空且仅含冻结事实 ID 或 MKT；MKT 绑定有效日期行情快照，不能替代必需段落的 PDF 事实。`kind=gap` 只能引用程序维护的 `GAP:<category>`，其文本由程序模板渲染，不能自由生成无依据断言；可选段“事实不足，未形成”同样由程序生成。ID 仅为依赖索引，不声称天然形成原子命题。模型必须将不同依据的断言分句；复核须检查一句内每个分句。保持 summary/business/financial/counterevidence 必需段、可选段缺口语义及 MKT 的既有边界。正文机械校验及每次补丁后均要求 business、financial、counterevidence 各至少引用一个对应必需类别的合格事实；非空风险/审计/附注组的入选事实须在 counterevidence 正文中被实际引用。发布事实不得悬空，未被正文引用的事实移出发布集合后重新检查至少三条及类别覆盖；有句子引用不证明语义正确，最终复核逐分句核查最强反证是否被淡化。
3. `review`：输入完整正文、冻结事实、主引文所在完整页/表及必要邻页，还有独立按类别召回的风险上下文清单。不能只阅读生成者的 claim。逐事实和逐句返回支持状态及带目标 ID 的错误类别；漏审、重复 ID、未知 ID、跨期/单位/口径误用、重要无据断言均拒绝。复核材料不足或超出上下文预算时失败，不静默去掉反证。

文档期、表格期间、行情日分字段记录：只有所选证据包的主片段或有已验证关系的期间片段支持的期间才允许用于事实及正文。文档标题年份不能自动成为全部表格的年份白名单；未进入包的页外上下文只能揭示错配，不能补成合法日期来源。数字换算沿用程序校验，语义对应与单位含义另由复核判断。

### 三、依赖失效与一次局部修复

程序维护 `fact_id / MKT / GAP:<category> → sentence_id` 反向映射，失效粒度为整句；分句核查不代表系统支持半句保留。事实删除、替换或被判不支持时，所有关联句子立即变为不可发布；禁止仅删编号而保留旧文字。无法区分一句中的受影响分句时使整句失效，不用正则拼补财务结论。变更传播后重新检查所有必需段和报告事实数；不得以缩短报告、删除主要风险来换取通过。

全流程共享一次模型修复机会；不是每阶段各一次。修复输入只含失败对象、原始诊断、直接关联证据、相关固定依赖及可修改 ID。可修改句子白名单 = 直接失败句子集合 ∪ 所有白名单可修改事实的全报告句子依赖闭包，允许跨 summary/financial 等段落。缺失必需段时显式授权该段预分配的新句子 ID；仅句子失败时冻结全部正确事实，不为了改句子而解冻事实。事实阶段缺少必需类别或不足三条时，程序可在八条上限内预分配未占用 fact_id；已满八条则只允许显式指定的可替换事实，不自动扩大事实数。此类新增事实只选既有候选包，不新增来源。白名单外句子以及公司、行情、来源身份冻结。错误定位不可靠时直接失败，不允许任意整篇重写。语义复核反馈包含具体事实/句子及失败原因，不接受仅有“报告不好”的全局修复指令。

补丁支持替换/删除白名单内事实及句子，以及上述明确授权的预分配 ID 新增；事实只能改选此次修复输入显式列出的已冻结备选包，不能新增来源。程序按失败类别提供有界备选包及完整依赖闭包；发起修复前须计算允许的替换组合在最终复核中展开的完整页/表/风险材料并去重，以备选集合最坏组合的上界核查复核预算，而非只检查每个备选包单独大小。装不下时缩小备选白名单但保留必需覆盖，仍无合法选择则在收费修复前停止。优先去重，不能为满足 2k–6k 目标删掉必要上下文，实际无法装入确认的预算则停止。新增句子只允许在显式获准的失效段落中使用程序预分配 ID；不能扩大其他段落作用域。修复前记录原对象哈希，合并时检查未授权对象完全不变；闭包外冻结对象即使原样回传也拒收；闭包内句子允许 `replace`、`delete` 或 `reconfirm` 操作，reconfirm 必须引用该句旧内容哈希，且 refs 必须与旧句完全相同，所引事实均未删除；仅允许所引事实不变或在同一 ID 槽位替换，不能借 reconfirm 删减依赖。若任何所引事实被删除，关联句子仅允许 delete 或正文确有变化的 replace，机械拒绝保留旧文字仅删引用。程序保留的 reconfirm 原文仍标记待重新校验和复核，不将模型确认当作通过。仅对本次补丁实际修改/删除的事实求依赖闭包，闭包内句子必须各有且只有一个操作；直接失败句子同样必须得到合法操作，漏项拒收。未实际改动事实的其余白名单句子可以不回传。修复未消除全部相关错误或引入新错误时停止，不消耗第二次修复。

阶段路径和调用上界：

| 路径 | 调用序列 | 上限 |
|---|---|---|
| 无修复 | 事实选择 → 正文 → 复核 | 3 |
| 事实选择失败后修复 | 事实选择 → 修复 → 正文 → 复核 | 4 |
| 正文机械校验失败后修复 | 事实选择 → 正文 → 修复 → 复核 | 4 |
| 复核失败后修复 | 事实选择 → 正文 → 复核 → 修复 → 再复核 | 5 |

每次补丁后先全量程序校验；最终发布对象必须有覆盖其完整内容哈希的独立复核通过记录。已用修复机会后出现任何后续错误均终止。同一已受理请求内仅按预先确认的有限分支执行，不创建新研究请求、不跨终态自动续跑。提供方超时或受理未知不进入自动收费修复；只核对原调用编号，缺少可校验响应即停止。

可使用动态 JSON schema 限定合法 ID 和 `additionalProperties: false`，但当前 pi/Hermes/provider 的原生约束能力须先核验；首版不得依赖尚未证明的能力，不得为结构化输出绕过无工具限制。本地 schema 校验始终保留，不因不支持原生 schema 放宽边界。

### 四、token、费用和缓存合同

以下是实验输入目标，不是提供方费用或 token 硬上限：

| 阶段 | 输入目标 |
|---|---|
| 事实选择 | 15k–25k |
| 正文 | 3k–6k |
| 复核（含上下文和风险材料） | 8k–15k |
| 仅失败时的局部修复 | 2k–6k，另预留复核 |

正常输入合计 26k–46k；最重的五调用路径输入目标为 36k–67k（正常三步+修复+再次复核），输出、推理、缓存计费及未知用量另计。单份合格报告均摊 token = 所有成功及失败尝试的全部调用 token 之和 / 合格报告数；亦可按各路径概率×路径消耗求均值，再除以成功概率，分母为零不可用。不能仅用正常路径目标推导整体节省率。上线门槛是每份合格报告总成本降低，不是用片段遗漏换取这些目标。先核验当前 tokenizer/usage 可用性；不能把字符计数标作精确 token。缺精确计数时用显式标识的保守估算做本地上下文预算，保留提供方实际用量和未知值。

本地实现按 UTF-8 字节检查输入（不是 token）：选择 75 KB、正文 18 KB、复核/再复核各 90 KB、修复 18 KB。这些上限随报价确认，子进程在采集前核对其摘要；不得把字节上限当作上述 token 目标已达成的证明。覆盖清单完整保存在冻结包，模型只接收类别数量；复核保留引文完整页，片段触及页边界或明确跨页时才加入所需邻页。

事实选择完成后、正文调用前，程序即按页/表和风险材料去重，预计算最终复核上下文并为正文预留输出空间；复核必需材料无法容纳时在正文收费前终止，不丢弃关键反证，也不额外调用模型瘦身。每次修复后重新计算。

调度器按状态图预留从当前步到独立复核终态的完整必需后续链路：select_facts 至少 3 次可用调用；事实阶段修复至少 3 次（修复+正文+复核）；compose、正文修复、复核后修复至少 2 次；review/再复核至少 1 次。时间按这些剩余调用的本地执行上界（包含当前适配器的终止清理余量）及发布校验余量预留；不足则不发起。预留不保证提供方按时完成或停止计费；仅有余量时才启用可选修复，不预留不存在的自动后续轮次。批次仍遵守当前最多 10 次模型调用的外层总预算；单报告最多 5 次，不暗中把多报告批次预算乘以报告数。240 秒单次等待、30 分钟单公司时间、100 次数据请求保持；输出 token 和费用无硬上限的披露不变。若实现调整报价或实际调用合同，报价身份必须版本化并让 Web/MCP 重新确认，不能复用旧报价授权新流程。

缓存分为：文档哈希+解析版本的本地解析缓存；文档哈希集合+分块/召回版本+证券/期间+结构化指标输入哈希+类别配额/上下文预算+扩展状态的确定性证据缓存；完全一致请求的跨请求模型响应缓存（仅索引通过对应阶段机械校验，且其事实/正文在最终语义复核通过后未被修复替换的响应；失败报告的原始响应只保留在调用账本）。模型请求键包含模型身份、阶段、schema/提示/校验版本、规范化输入哈希及依赖产物哈希。保留来源采集时间，不把旧资料伪装成本轮新采集。缓存命中仍做完整性与当前合同检查。不得把失败终态重新收费运行包装成缓存恢复。提供方缓存命中只记录实际值，不预先计入节省承诺。

### 五、版本兼容、诊断与代码落点

新流程使用独立内部流水线/schema 版本；旧证据、报告、质量记录与历史批次继续按原版本读取，已发布文件不迁移、不改写。句子依赖是新内部合同；正文可投影为现有段落，但复合引文必须升级显式报告/证据版本与 Web/MCP 的逐片段来源展示，不能伪装成旧单页引文。先发布能读旧、新格式但仍写旧格式的兼容读者版本，通过兼容测试后再启用新写者；生产回滚下限为该兼容读者版本。正常回滚须等待接收器空闲；紧急中断若另获授权，保留全部新版本非终态中间产物并显式标记停止/中断，只读展示，不由旧写者接管续跑或自动重收费。未完成兼容读者部署前不得产生新格式历史。首版跨版本模型响应不复用。所有模型调用的请求、响应和用量记录（包括无效响应）仍按调用编号保存在幂等账本以防同编号重收费；无效响应不得进入跨请求复用缓存。同编号核对仍重放既有结果或拒绝再次执行，不能删除无效记录来取得新调用资格；已验证的阶段产物与原始响应分开标记，缓存重放不能越过阶段校验。

| 模块 | 拟议变更 |
|---|---|
| `disclosures.py` | 证据块、分组召回、三阶段模型调用、句子依赖、补丁闭包、发布前复核绑定 |
| `automation.py` / `research.py` | 保留脱敏的失败阶段、端点、异常类别、尝试编号；不新增自动数据重试 |
| `contracts.py` / `research_service.py` | 版本化请求/报价及质量投影；批次与阶段预算、状态、幂等及历史兼容 |
| `research_client.py` / `mcp_server.py` / `web/` | 更新确认、失败与质量投影，以及新复合证据逐片段页码、原文、角色和关系标记展示；仍通过接收器访问 |
| `scripts/automation_model*` | 仅在需要且能力已验证时传递 schema/用量；保留无工具与进程边界 |
| `tests/` | 合成来源、依赖失效、预算路径、失败回放、兼容和用户流程反例 |

数据准备错误将请求失败、超时、返回缺字段、空数据和证券重复分开；日志采用白名单类别及经脱敏、限长的信息，禁止记录 token、请求头、完整配置或私人正文。公共界面展示稳定类别，详细内部诊断留宿主。质量计数区分生成事实、机械校验通过、语义复核通过、修复尝试/有效修复；后续段落失败不得把前面已经完成的计数重置为零。

### 六、实施顺序与验收闸门

1. 先实现脱敏诊断、阶段计数与依赖失效。通过合成故障反例和旧版读取测试，不产生真实模型请求。
2. 实现证据块、候选覆盖与三阶段流程；将实际失败模式抽象为合成 fixture，私人批次/日志不入 Git。正常、四调用、五调用及修复已耗尽路径都须有离线用例。
3. 独立验证模型适配器 schema 能力和上下文计量；不支持时保持本地校验，不切换模型或引入新依赖绕过限制。
4. 在用户确认模型、样本、调用/时间及费用边界后做新旧方案配对实验。建议另设调参集，并固定至少 12 个不参与调参的公司-期间验收样本，其中至少 8 个经人工确认有充分证据，覆盖至少 3 个行业及 4 类困难样本；每方案每样本独立运行 3 次。该规模只是试点建议，未授权执行，不足以作普遍稳定性证明。模型稳定性实验显式禁用跨实验运行的本地模型响应/阶段产物复用，每次使用独立实验编号和授权预算；不得删除已有调用记录后重试同编号。文档解析与确定性证据缓存可复用，提供方缓存命中单独报告；本地响应缓存正确性另用无需模型调用的回放测试验证。实验拆成独立有界请求，每个请求遵守原预算，不设绕开 10 次上限的大批次。冻结人工核验的证据/反证参考集；生产样本保存在宿主私有目录，Git 仅保留合成测试。
5. 记录事实/反证召回、事实与句子支持正确率、schema 成功率、机械/语义失败率、合格报告率、调用数、总 token、已知费用与未知用量、P50/P95 延迟。成本按全部尝试消耗除以合格报告数，分母为零则记不可用；配对比较保持模型、来源、冻结时间与规则相同。
6. 发布闸门：已知身份/日期/单位/引用/依赖失效反例必须全部正确拒绝；验收集中不得出现经人工确认的严重无据结论被放行；每个样本关键反证召回不得比基线退化。证据充分样本的成功率不得下降，平均每份合格报告总 token 目标至少下降 50%；失败率和置信区间必须报告，样本不足不得声称普遍稳定。任何质量闸门失败都优先阻断上线，不用成本改善抵消。
7. 实现验收运行 `make check` 与 `make test-mobile`，再按独立授权部署。生产复验完成新报告、原文、质量、价格确认、公司档案及退出隔离；回滚只能退至已验证的兼容读者版本，保证新旧历史仍可读取，不修改历史或自动重跑。模型或预算改变须再次确认。

本节评估规模和 token 阈值是待验证的工程目标，不是现有性能承诺。实施过程中若关键类别无法在小上下文内可靠召回，应暂停压缩或扩大显式预算，不把“少输入”当作成功。

### 七、方法来源与适用边界

- 共享 Wiki `concepts/typed-ai-agent-boundaries.md`：分离范围选择与细节生成；schema 不证明语义。
- 共享 Wiki `concepts/document-parsing-structural-fidelity.md`、`concepts/deterministic-analytics-llm-reasoning-boundary.md`：表格上下文保真，程序计算不替错误输入证明真实性。
- 共享 Wiki `concepts/agent-failure-closed-loop-evaluation.md`：真实失败模式转为最小防回归样例。
- [LlamaIndex CitationQueryEngine](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/query_engine/citation_query_engine.py)：借鉴引用节点编号与检索/合成分离，不照搬固定切块长度或把引用视为验证。
- [Pydantic AI output](https://pydantic.dev/docs/ai/core-concepts/output/)：借鉴类型校验、原生 schema 与明确错误反馈；运行时支持和语义准确性另验证。
- [LangGraph evaluator–optimizer](https://docs.langchain.com/oss/python/langgraph/workflows-agents#evaluator-optimizer)：借鉴生成/评价/反馈分离，采用本项目一次修复边界，不引入无限循环或框架依赖。
- [Docling table cell spans](https://docling-project.github.io/docling/concepts/serialization/#table-cell-spans)：借鉴保留表头和跨行跨列关系；不是采用新解析器的授权或效果证明。
