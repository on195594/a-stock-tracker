## 模块归属

| 模块 | 职责 |
|---|---|
| `web/` | FastAPI + Jinja2 服务端 HTML：OAuth/会话/CSRF、安全头、页面路由、展示规则，一个同源脚本 |
| `contracts.py` | 接收器、Web、MCP 共用的 pydantic 接口模型与错误码 |
| `research_client.py` | 经私有 socket 调用接收器；Demo 客户端只产生合成数据 |
| `research_service.py` | 宿主接收器：报价比对、按编号幂等、单次互斥、渠道限额、预算子进程、结果复验 |
| `mcp_server.py` | 本机 stdio MCP 服务：10 个工具，只读方法白名单，15 分钟报价暂存 |
| `automation.py` / `research.py` / `evidence.py` | 财报初筛冻结、覆盖、平均名次与证据选择 |
| `disclosures.py` + `scripts/automation_model*.{py,mjs}` | 原文采集、调用账本、批次发布、当前报告读取与共用数字校验 |
| `evidence_blocks.py` / `evidence_pipeline.py` | 确定性证据召回、事实选择、成文、一次有界修复与完整独立复核 |
| `opportunities.py` | 价格纪律参考的有界采集、程序计算与私有批次读取 |
| `auth.py` / `bounded_process.py` / `atomic_io.py` | 会话登记与签名、子进程边界、原子落盘 |

Web 不持行情或模型凭据，不打开数据库，不读取研究根目录；所有研究数据都经接收器读取。

## 网页研究请求合同

- **提交协议**（Web 与 MCP 共用）：客户端生成 32 位编号，提交完整请求与报价；接收器按当前配置重算报价，变化时返回 409 `quote_changed`。同编号同内容返回既有状态，不再执行，也不计入限额；同编号不同内容拒绝。
- **确认**：GET 永不提交；POST 必须勾选成本确认。报价变化时保留输入、重新报价并清除确认；被拒时保留输入并给出原因。
- **受理未知**：显示原编号与已确认费用，只允许用 GET 核对或按同一编号重新提交，不另起新编号，也不承诺提供方零费用。
- **财报报价**：含 `model_budget`（最多 10 次调用，本地超时 240 秒），没有 token 或费用硬上限，超时也不保证停止计费；页面逐字展示这一边界。初筛与价格参考不调用模型。
- **初筛**：新初筛固定 1500 次请求 / 3600 秒；续跑只接受七天内、门槛一致的检查点，报价为 `min(剩余待覆盖数 + 20, 1500)` 次。前置门槛为 0＜PB≤3、总市值≥50 亿元，这是工程默认值，未经收益验证。结果页预览每组前 3 名，完整排名经接收器分页读取（每页 50 行，游标绑定冻结批次与过滤条件）。
- **结果与档案**：每次读取都复验原始产物（在释放请求状态锁后执行重文件校验）；每次读取都重新读文件、核对哈希，字节完全相同的已复核报告在接收器进程内复用上次的校验结果（仅内存、最多 128 份，重启即清空）；失败、中断或校验错误不展示旧的成功结果。接收器返回内容若未通过接口模型校验，客户端一律按 `ResearchUnavailable`（MCP `service_error`）处理，不归咎为调用方输入错误。财报只放行复核通过的段落与引文，失败只显示固定的阶段与类别说明。`/runs` 在接收器侧按 `mode`、`code`、`limit`（1–20）、`cursor` 过滤并按研究链最新活动时间排序（支持链上任一节点作游标），`/reports?code=` 返回该公司最多 20 条已复核报告摘要；`/stock/{code}` 仅聚合接收器已复核报告与价格参考记录生成公司档案，不引入本地状态库。首页“公司”页按代码聚合各类型最近 20 条研究链，每家只显示最新可读报告与最新价格参考；失败、被取代或已过期的结果在展示层自动收起（不删除、不改写批次），仍可在分类记录页翻看。单家公司财报研究仍取全市场清单核对身份，但只冻结所请求的公司（不再保存全市场快照），所请求报告全部复核通过即记为 `completed`；官方原文 PDF 按 URL 与内容哈希在私有共享缓存中只下载一次，每次使用都重新核对哈希，批次内以硬链接共用，沿用首次下载时间；价格参考结果记录本次请求数、上限、耗时与停止原因，旧批次的用量保持未知（`null`）。

## 财报研究与结果读取

唯一可执行流程为 `evidence-first-v1`，生成 `cited-machine-research-v4` 报告。旧生成、修复、候选打分及页选取流程已经退役；显式配置 `legacy`、恢复缺少当前流程身份的旧研究批次均拒绝执行。v1/v2/v3 及 `line-ranges-v1` 报告读取已退役，旧格式拒绝投影；仅保留新流程仍使用的数字、单位、日期、路径和完整性校验。新流程历史结果继续可读。

必需段为摘要、业务、财务、反证；估值与改变判断的条件可缺省。摘要以“值得继续研究 / 需要谨慎 / 暂不值得”开头，表示研究优先级。程序从冻结原文构造证据块，模型只选择事实和解释已有证据；行情快照引用 `MKT` 不能代替必需段的 PDF 事实。数字、单位、日期与引用范围做机械检查，金额换算不代表语义正确，最终仍须独立复核；复核要求反证覆盖足以影响研究结论的主要风险，不要求列尽同类或金额较小的次要项；遗漏只依据可引用的证据块判断，整页上下文仅用于核对表头、单位与期间。

### 证据与修复边界

- 证据块为一个主片段及最多五个上下文片段，绑定文档哈希、位置、角色和关系证明；表头、单位、期间及跨页关系不明确时拒绝。Web/MCP 分片展示，不拼成虚假的连续引文。
- 按业务、财务、现金流、非经常性损益、资产负债和风险分组召回；各组优先最新期间的明确表格及本组主片段命中，避免通用政策靠跨类别关键词挤掉具体财务数据。先每组两个候选，必需覆盖不足时仅确定性扩展一次到六个；完整遗漏清单保留在冻结包。此排序是工程启发式，不保证找全关键反证。
- 正常路径为选事实 → 成文 → 独立复核；选事实/成文的机械错误与复核意见各有一次修复，最重为六次调用。召回时风险组多一个名额，并优先管理层讨论的风险小节（“可能面对的风险”“公司面临的风险和应对措施”）。成文证据按 ID 去重，显式提供风险事实编号；局部修复收到具体错误、获准对象和冻结候选，不额外联网。
- 事实变更必须处理全部依赖句子。复核指出段落缺口时，即使覆盖布尔值为真，也开放该段引用及对应类别事实的必要修复范围。未知证据 ID 可在冻结候选内纠正，不能新增来源。替换句子必须为完整对象；删除事实不能仅删引用保留论断；重确认须匹配旧句哈希和原引用。
- 修复后的最终内容重新执行机械检查与完整独立复核；每条事实与句子的支持判断仍逐条生效。首轮未指出、修复也未改动（含所引事实未变）的段落，再复核新提的段落级意见沿用首轮结论，并在质量记录 `carried_sections` 中披露；修复已用尽或仍失败就停止。旧流程的“剔除事实后择优发布”不再执行。失败不展示草稿，不删除调用记录来重试。

### 预算、缓存与验证

单家公司 30 分钟、最多 100 次数据请求；单报告最多六次模型调用，批次外层仍最多十次。每阶段发起前预留直到最终复核所需调用和时间。输入按 UTF-8 字节限制：选择 75 KB，正文 32 KB（容纳最多 8 个事实证据块），修复 50 KB（须容纳全部冻结依据与整份报告），复核/再复核 90 KB；完整页、必要邻页及独立风险材料不能靠裁剪关键反证来满足预算。字节不是 token，本地等待 240 秒不保证提供方停止计费，输出与费用无硬上限。

报价绑定流程和上下文合同，旧报价不能授权新流程。文档解析、确定性证据和已通过最终复核的阶段响应可在私有缓存复用；缓存身份含来源、模型、提示、校验和召回版本。原始请求、响应、用量仍按调用编号保存；同编号无有效响应时拒绝再次收费，缓存命中不冒充新调用。稳定性/成本实验禁用跨请求响应缓存。

质量记录区分生成、机械通过、语义通过与修复状态；公共错误仅含白名单阶段、类别和固定说明，不暴露凭据、原始提供方异常或私人路径。当前格式与安全反例必须持续回归。单个收费样本成功不证明稳定性或成本目标：多行业、困难证据及人工反证参考仍需独立验收，成本按所有成功和失败调用除以合格报告数统计。原方案的至少 12 个独立公司-期间、每样本三次重复及至少 50% token 降幅仍是未完成的评估目标，不是现有性能承诺。旧基线可从 Git 历史在隔离环境比较，不保留线上旧写者。

## 价格纪律参考

`price-reference-v2` 只由程序计算显式小池（≤5 家），不调用模型，也不以趋势或距离排除资料完整的公司。个股遇交易所除权参考价（`pre_close / 前收盘` 在 [0.3, 1)、窗口内 ≤2 次）时前复权到最新价格口径并逐次披露，其余不连续仍拒绝；`price-reference-v1` 与 `swing-observation-v1` 读取已退役，旧产物拒绝读取。有效期为后续 5 个交易日，不是持有期。过期后，服务端每次渲染都会隐藏观察线、失效线和距离；已打开的页面由脚本按上海日期隐藏；MCP 返回空价位，并清空相应的事实文字。

## 安全基线

- **认证**：GitHub OAuth 的 state 一次性、10 分钟有效，并与发起登录的浏览器绑定；单进程最多保留 128 条未完成状态，清理过期状态后仍满额则返回 429，不挤掉在途登录；只允许数字 ID 白名单中的本人。会话 cookie 为 `HttpOnly`、`SameSite=Lax`、`Secure`，有效期 8 小时，由服务端登记；退出或重新登录会使其他副本失效。
- **管理员密码登录（可选）**：`.web.env` 设置 `ADMIN_USERNAME` 与至少 16 字符的 `ADMIN_PASSWORD` 后，`POST /login/admin` 签发与 GitHub 登录相同的所有者会话；未设密码时该路由 404。`ADMIN_LOGIN_SCOPE=local`（默认）只接受客户端地址为回环或 `ADMIN_ALLOWED_IPS` 所列地址/网段的请求，其他请求得到 404；私网不算本地（同一 Docker 网络的其他容器也在私网内）。客户端地址只在 TCP 对端属于 `ADMIN_TRUSTED_PROXIES`（容器名、地址或网段，生产为 `nginx`，按容器 DNS 解析）时取 Nginx 写入的 `X-Real-IP`，否则一律取 TCP 对端，直连容器无法伪造；Nginx 由宿主 `nginxconfig.io/proxy.conf` 以 `$remote_addr` 覆盖该头，改动该文件须保持覆盖；`any` 对公网开放。Nginx 仅对 Cloudflare 公布网段内的对端采信 `CF-Connecting-IP` 作为客户端地址（`real_ip`），直连源站无法伪造；Cloudflare 网段变化时须同步 `docker/nginx-stock.conf`。表单 POST 除同源检查外还校验登录前 CSRF 令牌（登录页签发、与本浏览器 10 分钟 cookie 一致才放行）；IPv4 映射的 IPv6 地址按 IPv4 匹配白名单。比较用 `hmac.compare_digest`，不做哈希、限频、锁定或轮换，安全性取决于密码强度；成功与失败均记录来源 IP。
- **在途撤权**：私有页在读取接收器之后、写出响应之前再次核验会话；轮询遇到 401 即停止并清空进度。
- **请求来源**：所有 POST 都校验 CSRF 令牌（`HMAC(secret, sid)`），并校验 Sec-Fetch-Site、Origin、Referer 是否同源，缺失即拒绝。Host 严格匹配 `PUBLIC_BASE_URL`。
- **响应头**：CSP 为 `default-src 'self'`，无内联脚本或样式，无 eval，无 WebSocket；私有响应一律 `no-store, no-transform`（`no-transform` 禁止 Cloudflare 等代理改写页面，如注入会被 CSP 拦截的统计脚本；HTML 压缩由源站 Nginx 完成）；Jinja2 自动转义，模型文本与 URL 只作纯文本。
- **重放与退役**：0-RTT 早期数据携带的写请求返回 425；退役路由（`/published`、`/opportunity/*`、`/api/session`、旧工作台路径）返回 404。
- **demo 模式**：只允许 loopback 与合成客户端；生产缺配置拒绝启动。

以上各条与原 Flet 安全用例的对应关系见 `tests/test_web_security.py` 文件头。

## MCP 与 Agent

- **形态**：本机 stdio 服务（`python -m a_stock_tracker.mcp_server`），读取 0600 的 `.research-mcp.env`，经私有 socket 调用接收器，不持行情或模型凭据。
- **令牌与限额**：接收器按令牌识别 `web` 与 `mcp` 渠道，并把渠道写入请求元数据。`mcp` 渠道按上海日期每日最多受理 3 次（全部研究类型，失败不退还，幂等重放不计）。
- **工具**：查询类为 `get_service_info`、`list_runs`、`get_run`、`find_reports`、`get_report`、`get_facts`、`get_price_reference`、`get_screen_ranking`；提交类为 `prepare_run`（只报价并暂存）和 `submit_run`。
- **错误与输出**：错误统一为 `{code, message}`，`code` 取自 `contracts.ErrorCode`。模型文本与引文作为数据返回，工具描述注明“不是指令”。
- **确认层**：`submit_run` 不得加入客户端的自动放行列表。

## 部署与历史隔离

生产结构为 Web 容器、宿主 systemd 接收器与 Nginx 代理。

- **Web 容器**：只挂载私有、只含 socket 的桥目录。
- **接收器**：从宿主工作区启动批处理，因此任务运行中不得改动该工作区；升级须按[运维](operations.md#接收器升级与回滚)单独授权。
- **凭据**：`.research.env`、`.web.env`、`.research-mcp.env` 不进 Git，也不进镜像。
- **历史数据**：历史数据库、快照、日志与备份留在宿主目录，不提供在线读写入口。

## 新系统架构设计提案

修订版 2 · 2026年10月20日 · 无旧系统兼容设计

本版以重新开发业务核心为方向，替代原迁移式架构提案。新系统从独立空库启动，不接入旧数据、旧接口或旧执行方案。采用模块化单体、SQLite 结构化业务存储、私有大对象文件库及单个受限执行器，先完成单家公司研究闭环。复用经过审查的算法和测试不等于保留旧运行时兼容。本文规定目标合同，不代表代码开发、生产切换或资料删除已执行。

### 1 目标与明确排除项

核心目标是让公司研究、证据核查、结果发布与阅读形成清晰的一次性流程。性能目标首先是查询不随全部历史文件线性扫描、报告发布不依赖多份业务数据相互追平、一次运行不受后续部署改变。远程模型的必要串行等待不会因重新开发自动消失。

新系统不导入旧报告、旧账本、墓碑或旧数据库，不提供旧格式适配器，不进行新旧影子对照和增量追平，也不自动研究历史公司来填充空库。旧代码与资料原样离线保留，作为需求和核账参考，不成为新系统依赖；不兼容不等于授权删除。

新系统的主业务仍包括财报研究与独立价格参考；价格参考由确定性程序计算，不因重构改为模型估价。首个编码纵切仅完成指定公司的财报研究、反证和来源展示，不等于已获准缩减首发产品范围。首次上线是否可暂缺价格参考、初筛或 MCP，须作为明确范围决策确认。暂不建设多用户、自动交易、自动收费队列、分布式协调或通用工作流平台。

### 2 模块与进程边界

入口适配层处理浏览器或 MCP 输入、会话和展示；应用服务处理确认、幂等、预算、查询与发布；研究执行器处理已确认的冻结输入并返回候选结果。它们属于一个应用，不拆成多个独立部署的业务微服务。

保留真实的权限边界：对外入口进程不得直接持有行情或模型凭据；受保护的应用服务经窄接口校验身份、报价和预算后才启动受限执行器。执行器不拥有发布权限，不能自行把候选结果变成用户可读报告。私有 socket 可作为单机传输选择，但旧 socket 协议、接收器名称和文件布局都不是兼容要求。

一次只运行一个已授权的有界研究；资源、输出和时间均设边界。使用独立运行身份和目录权限限制执行器访问，凭据不进入报告、日志或静态资源。最终部署拓扑须验证入口失陷不能直接读取凭据或绕过受保护服务的确认与预算检查。

### 3 唯一业务存储与五类核心记录

SQLite 是结构化业务数据的唯一权威，保存确认内容、冻结输入、调用账本、结构化报告正文、验证结果和发布状态。私有文件库只保存 PDF、原始响应等大对象。JSON 可以作为受约束数据库字段或导出格式，不再成为另一套权威报告文件。

数据库位于本地持久磁盘，启用外键及必要唯一约束，使用短写事务。WAL、连接数和 checkpoint 策略根据离线基准配置，不把增加连接当作并发写扩容。业务账本不是缓存，不能仅靠报告文件重建。

- Company：稳定的规范化证券身份为主键，名称为属性；不以名称推断关联。
- ResearchRun：保存 generation_id、run_id、请求内容摘要、不可变确认与预算、冻结输入、运行版本、阶段及终止原因；generation_id 与 run_id 组成唯一幂等身份。
- CallAttempt：关联 run_id，记录阶段、尝试号、预算预占、提供方请求编号、请求与响应摘要、用量及结果状态；同一运行的阶段尝试号唯一，未知用量不得记作零。
- Report：以 report_kind 区分研究及价格参考，关联公司和运行，保存结构化正文、来源引用、输入摘要、模型或确定性计算版本、验证版本、质量状态和发布时间；按 company_id、report_kind、published_at、report_id 建索引，正文发布后不原地改写。
- Artifact：记录内容哈希、类型、私有对象位置、来源、首次取得时间和派生算法版本；文件不存在或哈希不符时不得被视为有效依据。报告与附件的关系使用必要的关联表，不由目录扫描推导。

### 4 冻结输入与复用规则

ResearchRun 的冻结输入明确列出文档及证据版本、行情快照、模型、提示、解析与校验版本。它可以是规范化的结构化字段，不必另建通用输入资产平台。输入摘要由固定序列化规则计算，确认后不得静默改变。

相同 PDF 与相同解析算法可以复用确定性派生结果；行情变化不能使文档解析失效，却必须使依赖行情的研究结论重新计算。原文或算法变化产生新版本，旧资料复用继续披露原取得时间。首次版本不建设跨运行模型响应缓存，避免提前承担复杂的复核通过传播和失效合同。

模型只解释明确的来源事实。证据缺失、冲突和校验失败不能由模型补全。独立价格参考冻结行情时点、公式、参数及有效期，由确定性程序计算；其运行不产生模型 CallAttempt，也不将财报质量通过等同于投资效果。价格请求和确认使用新合同，不保留旧 schema。

### 5 执行状态与收费正确性

正常流程为冻结输入、准备证据、选事实、成文、机械校验、独立复核和发布。修复次数、模型及请求与时间预算属于新报价合同；任何变化须重新确认，不把旧系统数值无条件继承为新系统规格。必要的数据依赖串行执行，不以并行扩大收费尝试。

ResearchRun 区分 accepted、running、completed、failed 与 outcome_unknown；当前阶段和阶段时间记录在运行中。CallAttempt 另行区分 prepared、dispatched、completed、failed 与 outcome_unknown。报告是否可见由独立的发布条件决定，不仅看运行状态或子进程退出码。

发出模型请求前先可靠登记调用编号和预算预占；发送后只有响应及用量持久化并核验才能推进。若进程在发送边界崩溃，无法证明未发送时按 outcome_unknown 处理。本地数据库无法保证提供方恰好执行一次，不能自动换编号、返还未知预算或重发收费请求。

输入冻结、调用账本、幂等与固定运行版本必须在首次真实研究前完成。重启只恢复可核对状态，不自动恢复收费执行。确定性计算可在输入身份和授权范围内重做，但不得因此隐含启动新的外部调用。

报价区分本地调用次数与时间限制、提供方 token 限制和实际费用约束，不能将字节或本地超时包装成费用硬上限。不能可靠封顶的费用与超时后仍可能计费的情形必须明确披露，失败和未知结果仍保留用量未知状态。

### 6 验证发布与查询合同

执行器返回候选结果后，由应用服务核对来源、机械规则和独立复核结果。大对象先可靠落盘并校验，再在一个数据库事务中写入报告正文、来源关系、验证结果及发布状态。普通报告不再在文件与数据库各维护一份权威正文；远程调用和重文件处理不得占用数据库写事务。

文件已落盘而事务失败时只留下未引用对象，不产生可见报告；事务提交而响应丢失时查询原 run_id，不能重复执行。发布幂等绑定运行与发布身份，多个合法报告可以引用同一内容对象，不能用全局唯一正文哈希阻止合法发布。未引用文件不自动删除。

拟议接口为公司列表、公司详情、报告分页、报告详情、运行状态和报价提交。API 路径在实现时统一定稿，不兼容旧路径。列表用索引及时间加 ID 游标读取有界结果；公司最新报告直接查询已发布记录，摘要取报告字段，不预建 CompanyView、ReportSummary 等持久物化投影。

状态查询只返回进度和固定错误类别，不读取或传输完整报告。详情只展示已发布且未被标记完整性异常的内容；价格到期、会话撤销及访问控制仍在请求时判断，不能固化为永久有效。

### 7 完整性信任模型的明确选择

本版建议的新合同是：采集、派生及发布时验证对象哈希和来源关系；列表读取数据库保存的已验证报告快照；访问原始附件时重新核验对应对象。已知缺失或损坏的对象及其受影响报告须被隔离或明确标记，不能继续冒充正常。完整性检查工具应可由运维明确运行，但本文不建立自动巡检计划。

这一方案不证明每次列表展示时所有原始 PDF 的当前字节仍然完整，不能声称等价于原方案逐次读取全部来源。它将即时信任边界放在受控业务库和发布过程。若要求每次展示都证明全部来源仍一致，就必须保留额外的逐次来源核验并接受其成本。

该信任模型列为实施前必须确认的设计决策。用户要求不兼容旧数据，并不自动授权降低完整性保证；在决策明确及测试通过前，不得把取消逐次来源读取当作既定实现。认证、在途撤权、CSRF、同源、Host、CSP、私有响应 no-store 及路径防护均不是兼容包袱，必须保留。

### 8 系统代际隔离与版本运行

新实例生成独立 generation_id，所有请求、报价、确认凭证和会话均绑定该代际；服务器验证代际而不是只依靠客户端编号前缀。旧协议、旧报价、旧会话与旧请求明确拒绝，不自动映射为新请求。用户必须重新登录、重新报价并确认，新系统不需要导入旧账本来执行此隔离。

每个运行绑定不可变代码版本、依赖环境及模型与验证合同。新部署只影响后续运行，不能修改在途进程所用代码。业务库、大对象与发布目录分离；同一新系统后续升级需要自己的 schema 演进和备份策略，不等于恢复旧系统兼容。

切换前旧系统须停止受理，既有执行结束或被明确隔离，确认其不能继续发布或发起收费调用。旧未知费用记录留在旧归档供核账，不导入为可恢复任务。新系统从空库开放，故障时停止新受理并在新体系内恢复，旧写者不得接管新库。

### 9 验收与恢复边界

使用新格式合成数据验证 10、100、1000 条历史及冷暖读取、并发访问。记录 P50/P95、CPU、内存、读取量和查询计划；常规分页不能枚举全部历史文件。性能目标在代表性机器基线后确定，不承诺未经实测的百分比提升。

必须覆盖重复提交、报价变化、旧代际重放、未知模型响应、原文损坏、发布断点、会话撤销及版本固定。正确性按新业务规格与独立证据判断，不要求与旧实现输出逐项一致。

备份包括一致的 SQLite 快照及其引用的大对象集合。恢复到隔离环境后校验数据库版本、对象哈希、发布引用和调用账本；在排除备份之后已发生但未记录的调用之前不得重新开放收费执行。恢复不能把已有请求重新当作新请求；必要时更新运行实例栅栏并保留旧代际拒绝规则。
