# 研究工作台的模块与数据合同

用户只需回答三件事：接下来研究谁、关注公司变了什么、下一步核查什么。

```text
config/anchors.json ──→ 同业发现 ──→ 关注
TuShare ──→ 独立 worker ──→ 不可变事实快照 ──→ 变化 / 已阅 / 下一步
交易日历证据 ──→ 提交时冻结目标日             ↑
                                   私人 SQLite 工作区
```

| 模块 | 职责 |
|---|---|
| `config.py` / `paths.py` | 本项目参照 JSON、工作区与数据目录 |
| `calendar.py` | 独立日历采集、来源证据、完整性/覆盖/原子发布、最近已证明交易日 |
| `research.py` | 同业枚举、严格年度 ROE 选择、PB/ROE 排序及本次事实采集 |
| `watch.py` | 冻结个人关注的事实更新；不重筛，不改变历史同业名次 |
| `workspace.py` | 三表、schema/模式、快照导入和持久化安全 |
| `services.py` | 鉴权后的研究查询/写入、事实比较、任务受理 |
| `worker.py` | 独立任务执行、请求/快照身份验证、发布与故障恢复 |
| `app.py` / `auth.py` | Flet 页面、会话、OAuth/ASGI 边界 |
| `maintenance.py` / `manage.py` | 初始化、合成 demo、导入、离线备份/恢复 |

研究采集不读取原 tracker.db 或财报观测库、不执行旧 Python 配置、不用旧缓存冒充本次核查。没有旧评分、QFQ、收益基准或通用财务物化链。日历是研究流程仍需要的唯一周期维护。

## 行为合同

- 同业发现保持 peer-screen-v1：沪深主板非金融、TuShare 粗行业、按市值最多 50 家，PB 升序/三年 ROE 均值降序名次取平均，并列取平均名次，展示前三和参照。行业标签不证明业务可比；排序不等于买入评分。
- 财务要求连续三份年度、明确证券身份/公告日期/修订选择；重复、截断、非有限值及版本冲突都必须显式处理。每次提交重新核查，取得时间不能冒充公告日。
- 我的关注按异常、公司状态、指标/口径变化、仅日期、无变化分组。只比较实际已阅基准到当前可用事实，不能跨快照拼接“完整”资料。
- 关注无需笔记；保存笔记不推进已阅。已阅独立显示，必须再次验证实际显示快照、最新失败、日期与 revision/updated_at。未关注、损坏、缺口、过期版本或撤销授权不能越过这些校验。
- 更新冻结提交时的目标日与范围；同 ID 不同意图拒绝，同范围在途合并。worker 在网络访问前释放数据库事务，关页面不取消任务；结果固定路径、不可覆盖、哈希与任务身份一致才能登记。
- 登记快照前同步文件及工作区内的各级父目录；同步失败不登记成功。崩溃恢复再次执行同步与身份检查，不能仅以文件存在判断成功。
- 三张业务表 `screen_runs`、`watch_items`、`update_jobs` 保留 schema 名称以兼容旧研究记录。它们不是旧行情库；历史快照的 `source=tracker` 及规则身份也不改写。
- 失败/partial 与上次完整结果分开；最新失败不能自动换已阅基准。暂停不删除笔记，恢复不重新排名。

## 运行与验证

一个 Web、一个串行 worker、一个独立日历命令。Web 只有 OAuth 配置；worker/日历只有行情凭据。Web 只读挂载整个日历目录，原子更新后能读到新文件；私人研究目录不经静态服务暴露。

测试保留原研究数据、鉴权、冲突、任务恢复、日历失败回滚的反例，并验证不需要相邻项目。浏览器覆盖空工作区扫描→关注→保存→已阅、断线重连、迟到结果及手机宽度。真实接口、本人 OAuth、手机和正式迁移需单独验证，不能用离线绿灯替代。
