# a-stock-tracker 进化路线图

**版本：** v1.37
**基线日期：** 2026-09-07

## 目标

将项目建设为 A 股选股与买入决策支持系统，帮助用户回答“买什么、什么时候买”，提高获得较高风险调整后收益的概率。系统不承诺收益，也不把工程完整、报告生成或模型调用成功等同于投资有效性。

当前生产仍是固定 35 股跟踪系统，不代表全 A 股选股能力。

## 当前事实

- Framework A 尚未证明跨时间、跨窗口的稳定截面排序能力；
- `buy_strong=44` 是可得分上限校准，不是收益最优门槛；
- L3 v2 只是 `close < MA120 × 0.65` 的极端下跌风险提示；高分候选 352 次评估零触发，已不再参与候选分层；
- legacy outcome 使用未复权价格，不能作为最终策略真相；
- 固定 watchlist 存在股票池效应、行业集中和选择偏差；
- 权重、阈值和新框架在阶段一结论前保持不变。

## 三阶段执行路线

### 阶段一：证明现有系统是否有效（当前）

目标：判断 Framework A 是否具有可复验投资价值；L3 v2 已完成判定，仅保留为极端风险提示。

执行项：

1. 比较 watchlist 等权组合与沪深 300 全收益基准；
2. 使用 QFQ 个股总收益评估 30/60/90 日结果；
3. 按 `score_date` 计算截面 Spearman IC 及时间汇总；
4. 报告 Q5−Q1 spread、最大回撤、时间批次和同股事件去重；
5. 保留 L3 v2 正常/触发后的收益和回撤观察，但不作为买入门禁；
6. strong 候选 352 次评估零触发，已判定当前规则无实质选择性；
7. 用自动 QFQ 策略报告替换 legacy outcome 展示，不建立并行 shadow 系统。

退出条件：

- 明确 Framework A 是有效、需简化、需重做还是应停止；
- 已明确 L3 v2 仅保留为极端风险提示，不参与候选分层；
- 默认报告采用可解释的总收益口径；
- 结论不依赖单一日期或重复事件。

#### 2026-09-07 缺陷修复修订（优先于下方原协议）

投资审查确认PB历史长度混用、回撤仅采样批次端点及量化输入快照缺失。此次修复是数据与评估纠错，不是因收益不佳调参；权重、44分阈值和35股股票池不变。

- PB统一消费当日TuShare物化分位。历史限制在估值日前十年内，按月取最后有效观察（包含当月，120–121个月桶才合格）；不足十年、旧数据或非法分位保持缺失，不再由价格/BPS和无日期历史重新覆盖。
- 新prediction记录原始基本面、实际评分输入、配置、分项得分、缺失情况、定性缓存日期及实现指纹。只新增可空快照列，不回填或改写历史评分。
- `weights_hash`升级为包含评分/输入处理源码、输入策略版本和共享包版本的16位SHA-256指纹。新hash与历史三个8位hash隔离；源文件的非语义修改也可能保守切开cohort，积累证据期间避免无关改动和包升级。
- 原始收益、IC、spread、截面选择仍是**评分日收盘起算的研究标签**，不是可成交收益；30/60/90是自然日。保留端点回撤并更正名称，新增持有期间日收盘最大回撤；缺必要日线则N/A，批次间空仓零收益。
- 报告和Telegram明确：验证对象是Q5，不是≥44分名单；跨行业偏差、旧定性输入、费用、成交约束、仓位和退出尚未解决。定性冻结日期来自prediction快照，旧记录不以当前缓存补造历史判断。
- **原2026-09-20/09-23最终检查时间不适用于修正后版本。** 修正前cohort仅保留历史诊断，不能证明修正后算法有效。新cohort从首次完整写入起重新积累；至少30/60/90日分别3/2/1个合格非重叠截面及完整行情/基准、快照后才进入研究方向复核，之前为`INSUFFICIENT_EVIDENCE`。数量门槛不是统计显著性或实盘采用门槛。
- 后续行业内排序、去定性分/单因子消融、下一可交易时点及费用验证，仍在阶段一方向复核后单独预注册；不把本次修复宣传为已解决行业适用性或已建立组合风控。

#### 阶段一原始裁决协议（2026-08-12 预注册；修正前历史口径）

本协议冻结至阶段一最终裁决，不因后续收益好坏临时改动。阶段一只评价当前固定 35 股观察池中的 Framework A 排序，不证明全市场有效性，也不授权真实组合配置。评分、权重、`buy_strong`、股票池、cohort 合并规则和报告算法保持不变。

证据只取默认 QFQ 策略报告中最新评分版本及已核实语义等价、qualitative provenance 合格的 cohort。个股使用前复权总收益，基准使用沪深 300 全收益；30/60/90 日窗口必须按 `score_date` 形成完整、非重叠截面，同股事件不得重复计数。legacy outcome、旧未复权价格、人工挑选日期、盘中结果和本协议之后新增的指标均不得参与裁决。

两个检查点：

1. **2026-08-21 后中期检查**：预期至少有 3 个 30 日非重叠截面和 1 个 90 日非重叠截面；只记录方向、数据缺口和临时分类，不作最终去留裁决。
2. **2026-09-20 后最终检查**：在其后首个交易日的完整日终数据链完成后执行；预期至少有 2 个 60 日非重叠截面，并同时读取届时成熟的 30/90 日窗口；输出“继续 / 简化 / 重做 / 停止”之一，证据门槛未满足时输出 `INSUFFICIENT_EVIDENCE`。

任一检查点未达到预期截面数、截面完整性门槛、行情/基准新鲜度或 provenance 要求时，结果只能是 `INSUFFICIENT_EVIDENCE`，顺延收集，不允许用不完整数据强行归类。

“成熟窗口”只指默认报告中的 30 日、60 日、90 日三个跨度，不指该跨度内的单个非重叠截面。每个跨度内全部合格截面沿用默认报告既有聚合结果；“日”、收益起止价和非重叠间隔均沿用当前默认报告算法，不在本协议中重定义。不同跨度对同一预测的多期限观察是有意的期限稳健性检验；同一跨度内不得重复计入同一 `score_date`/股票事件。

每个成熟窗口使用三项方向证据：截面 Spearman IC、Q5−Q1 alpha spread、Q5−观察池等权累计收益差。`> 0` 为正向，`< 0` 为负向，等于 0 为中性；沪深 300 相对收益和最大回撤只作风险解释，不替代上述排序证据。证据门槛未满足时直接输出 `INSUFFICIENT_EVIDENCE` 并顺延收集，不进入以下四级裁决；满足时按以下顺序裁决，命中即停止：

1. **继续**：至少两个成熟窗口的三项方向证据全部为正，且没有成熟窗口三项全部为负。含义仅为进入阶段二扩大股票宇宙和样本外验证。
2. **简化**：不满足“继续”，但至少两个成熟窗口各有不少于两项正向证据，且没有两个成熟窗口各有不少于两项负向证据。下一步只允许做现有 Framework A 的组件消融或更简单排序基线，不增加新框架。
3. **停止**：所有成熟窗口的三项方向证据均非正。停止 Framework A 的生产候选扩张；保留历史数据供审计。
4. **重做**：其余相互矛盾、不稳定或明显依赖单一窗口的结果。回到投资假设和特征定义，不在现有权重上调参补丁，也不进入阶段二生产扩张。

裁决记录必须列出每个窗口的截面数、样本数、三项方向证据、Q5与观察池及沪深300收益、最大回撤、数据截止日、weights hash、provenance口径和缺失项。不得因为真实持仓盈亏、宏观判断、单只股票表现或L3提示覆盖上述裁决。

### 阶段二：离线扩大股票宇宙

仅在阶段一形成稳定评估口径后启动。

1. 构建 300–500 股历史截面；
2. 做行业分层或行业中性评估；
3. 比较不同市场阶段的 IC、spread、命中率和回撤；
4. 纳入交易成本、停牌、可交易性和样本外验证；
5. Framework A 无效时先简化或重做，不叠加新框架。

退出条件：至少一个简单框架显示稳定、可解释且不依赖固定股票池、单一行业或单一时间区间的排序优势；否则停止生产扩张。

### 阶段三：生产决策闭环

仅在阶段二通过后启动。

1. 建设动态候选池；
2. 上线经验证的买点信号；
3. 增加仓位、集中度、退出条件和风险预算；
4. 先自动小流量验证，再影响用户买入结论；
5. 持续监控收益、回撤和换手。

退出条件：系统能回答“买什么、为什么现在买、买多少、何时退出”，且风险调整后结果优于明确基准。

## 工程减法

### 第一批（2026-07-28）

从活动产品链直接删除：

- Framework B report/cohort、CLI 和 cron；
- L3 v1 计算、新写入、回填和测试；
- Google Sheets 同步及依赖；
- 在线 Gemini v1 调用；
- qualitative v2 acceptance；
- weekly PM loop。

历史数据库中的 Framework B、L3 v1 字段和记录保持只读，不做破坏性迁移。daily 优先使用 QFQ 最新价；定性分只读取已有本地缓存或固定 fallback。

### 第二批（2026-07-28）

- 把最小 QFQ 总收益、IC、spread 和回撤计算进入默认自动报告；
- 让自动 QFQ 任务同步沪深300全收益指数；
- 提取纯计算后删除 outcome shadow 与 migration；
- 删除 M4/M5、历史 qualitative pilot、手工 qualitative shadow/writer 和对应测试、脚本、治理文档；
- 删除已完成且只能手工运行的离线 L3 v2 backtest 及复审产物；
- 用 Git 历史替代“冻结代码备用”。

第二批已完成。生产数据库中既有 shadow 表和 qualitative v2 行仅作历史兼容保留，不再有写入、迁移或手工执行入口。

### 阶段一收口（2026-07-28）

- Telegram 从“主推/候补”降级为未验证观察名单；
- 策略报告改为 daily 后自动刷新，删除手工 `accuracy-report`；
- 删除 legacy `outcome-update`、18:00 cron、Phase4 通知与新库里程碑表；
- 历史 outcome/benchmark/alpha/estimate 与里程碑数据只读保留；
- 报告只使用最新 `weights_hash` 且 qualitative provenance 已记录的 cohort，IC、spread、组合收益和 L3 统一使用完整的非重叠截面；
- 增加观察池等权组合，直接展示 Q5 相对固定股票池的排序收益差。

## 长期保留

- TuShare 数据采集、readiness、来源纯度和原子物化；
- QFQ 行情缓存；
- Framework A 纯评分与决策时快照；
- daily、自动 QFQ 策略报告与 Telegram 观察名单；
- 核心数据库和交易日语义测试。

## 防止再次过重

1. 新任务必须验证 alpha、买入时点、回撤或当前生产不可逆风险；
2. 不保留只能手工执行的备用代码；
3. 不为只读研究建立 migration、seal、reviewer 或 authorization；
4. 不建立与默认产品并行的报告或数据真相；
5. Git 历史承担恢复职责；
6. 达到阶段退出条件后必须形成继续、简化、重做或停止的决定。
